# 一、AVC 投运率算法

> 依据附件6 §一。投运率考核 **AVC 装置在不在线**（时间记账），与调节合格率是两个独立维度；投运率不适用 §二 的免考，它有自己的免责——"扣除电网原因退出时间"。

## 1.1 公式

```
AVC 投运率 = AVC 投运时间 / 并网运行时间 × 100%
合格标准：≥ 99%
考核单价：每缺 1 个百分点 = 额定容量 × 0.02 分/万千瓦
```

- **并网运行时间** = 统计周期（月）内并网主体并网运行的总分钟数。
- **AVC 投运时间** = 并网运行时间 − AVC 退出时间。

## 1.2 投退信号来源

**`yc_history` / `yx_history` 表**（AVC 投退 yx 点）：

| 字段 | 含义 |
|---|---|
| `yc_num` | 遥测点编码 |
| `yc_time` | 时间戳 |
| `yc_data` | `1` = AVC 投；`0` = AVC 退 |

- `yc_time` 就近取整到分钟（秒 ≥ 30 进位），与 `his_curve_sv` 共用时间原则。
- yx 为阶跃保持量：`yc_data` 在两次变位之间**保持上一值**（取最近一条 ≤ 当分钟）。
- **点号**：合成库 = **yc3009**；真实候选 = **yx1001**（对端 `AVC_INFO.AVCStatusYxNum`，2026-08-18 考据）——⚠️ **撞号警示**：真实库 yx3009 = 四号机组下闭锁总信号，语义不同，真实现场核对后必须换号（见 [数据源头（草稿）.md](数据源头（草稿）.md) 定号一览）。

## 1.3 逐分钟投运状态判定

对统计周期内每一分钟 `t`：

```
并网(t)   = 该分钟并网主体是否并网运行
           （信号点：yc511 正母 / yc512 副母，值 = 带电×10 + 机组数、≥10 即并网——
             合成库已定义，真实现场待核对，见 v5.0 §8.3）
avc_in(t) = 主 AVC 投退点在 t 时刻的保持值（1=投 / 0=退）

if 并网(t):
    if avc_in(t) == 1:  → 投运分钟 +1
    else:               → 退出分钟 +1（进一步分：电网原因 / 非电网原因）
# 未并网(t) 不计入任何分钟
```

## 1.4 免责：扣除电网原因退出时间

投运率免责是**时间扣减**（与调节合格率的免考无关）：

```
AVC 投运时间 = 并网运行时间 − Σ退出分钟
退出分钟    = 非电网原因退出分钟 + 电网原因退出分钟
免责       = 扣除 "电网原因退出分钟"（不计入分母的惩罚基数）

即：惩罚性退出 = 非电网原因退出分钟；电网原因退出不罚
```

> **退出原因点位**：**yc521（正母）/ yc522（副母）**——0=未退 / 1=电网原因（免责）/ 2=非电网（扣罚）。合成库已定义（`tools/avc-data-gen/config/points.yaml`，映射自 `docs/外部DB/JS计算引擎说明.md` 的对端 JS 引擎逻辑）；真实现场待对端 JS 引擎部署与点号核对（v5.0 §14-8）。

## 1.5 统计

```
投运率 = 投运分钟 / (投运分钟 + 非电网原因退出分钟) × 100%
        （电网原因退出分钟从分母扣除）
缺额   = max(0, 99% − 投运率)
考核量 = 缺额百分点 × 额定容量 × 0.02 分/万千瓦
```

## 2.0 三阶段管线（总览）

一道指令的完整处理分三阶段（Leo 2026-08-14 拍板，工程实现见 v5.0 §8.2）：

```
指令（warn_info, warn_type=5）
 │
 ├─ 阶段一【门控前置过滤】（调用方做，不进 judge）
 │    读 yx：AVC投退 + 远方就地总（yx2003 = OR(yx12 正母, yx23 副母)，2026-08-18 定号）
 │    AVC 退出 / 就地（本地手动）时段的指令 → 剔除，不算电厂的锅
 │
 ├─ 阶段二【judge 包络判定】（本算法 §2.1~§2.6）
 │    解码 + 两档平行包络判定；只出两态结论 + 「判不了」信号 + 窗口事实
 │
 └─ 阶段三【免考后置应用】（非判定）
      读对端 yx501（全厂一个，0/1，对端 JS 算好）：
      该档 PENALIZED 且 yx501=1 → 该档免考（不算不罚；分母口径见 §2.7——2026-08-19 拍板附件6 原始分母，免考不剔分母、罚款缺额剔免考待确认）；否则该档罚
```

- **门控点未核对前空转**：`gate_enabled=0` 时阶段一直通（v5.0 §14-7；合成库点位已齐，联调置 1）。
- **免考判定（Q vs 极限）是对端义务**——VQMS 只读 `yx501` 结论值，不背判定义务；免考是后置应用结果，**不是判定的第三种输出**。

## 2.1 判定对象与目标

**对象**：一条 AVC 指令（发令事件）= `warn_info` 表里一条指令记录（`warn_type=5`，含目标值或增量值）。

**目标电压 `V_target`（kV）**——指令解码后的绝对目标电压：
- **目标值形态**：文本数值 ÷ 100 → kV（如 `22315` → **223.15 kV**）
- **增量值形态**：解码 4 位编码 → 增量幅值 × 100V × 方向，再 **+ t₀ 当前实时母线电压** → 绝对目标（如 `2202` = +200V；当前 234.25 kV + 0.2 → **234.45 kV**）。**第 2 位 = 0~5 循环码（Leo 2026-08-19 告知）——不参与 `V_target` 数值计算**（方向×幅值公式本就不含它）；合法值域 {0..5}，出现 6~9/非数字 → `Undecodable{循环码非法}`；轮转规律（疑为指令序号防丢令）待真实数据实证

> 指令只考虑电压指令；无功指令留接口。**不从 `his_curve_sv.plan_SV` 取目标**——目标来自 `warn_info`。**解码留在 judge 实现内部、调用方不预算 `V_target`**（解码位定义随循环码定稿会变，预算会迫使调用方改动——v5.0 §8.2 要点）。

## 2.2 数据对齐（按分钟）

每分钟一条 `his_curve_sv` 记录，携带该分钟的 `high_SV` / `low_SV`（kV，**判定用字段**）。

- **时间原则**：原始 `save_time` 就近取整到分钟（秒 ≥ 30 进位）；取整幂等，reader 内边界裁剪 + 调用方窗口对齐双重取整无害（v5.0 §5 时间契约）。
- **按主母线分组**：`busbar_num`（来自 `yc_history` 主母线号点）筛选本指令作用的主母线。
- **基准时刻 `t₀`** = 指令下达时刻（`warn_info.warn_time` 就近取整到分钟）。
- **第 k 分钟组**（k=1,2,…）：`[t₀ + (k−1)min, t₀ + k·min)` 区间的记录。
- **缺分钟如实上报**：judge 不自行处置，记入 `completeness`（窗口完整度）——处置归策略层（§2.9）。

## 2.3 区间聚合（包络并集）

N 分钟窗口内每分钟一组 `(high_SV_k, low_SV_k)`，聚合为**一组综合区间**：

```
综合区间 [L_N, H_N] = [ min(low_SV_1..N),  max(high_SV_1..N) ]
```

- `L_N` = 窗口内所有分钟 `low_SV` 的最小值（下包络）
- `H_N` = 窗口内所有分钟 `high_SV` 的最大值（上包络）
- 语义：窗口内电压摆动**曾覆盖到的最宽范围**。

## 2.4 分档判定（核心）

### 2.4.1 整定参数

| 参数 | 含义 | 取值 |
|---|---|---|
| `T_fast` | 快速性档窗口上界 | **∈ [1,5) 整数可整定**（Leo 2026-08-14 拍板；原"5 min"作废），**默认建议 4**（默认值本身待 Leo 正式确认，种子已插 4——2026-08-19 交叉核对修正：原 4_1"默认 4 已拍板"系回写过度表述，2026-08-14 原始记录为"待定建议 4"） |
| `T_econ` | 经济性档窗口上界 | **= 5，写死**（Leo 2026-08-14 拍板；原"待定上限"作废——指令实际 5 分钟间隔 → 判定窗口 = 5 分钟） |

> "1 分钟"原始合格线**不再单列**（已废）；`T_fast` 现场可整定（存 `vqms_judge_param`，v5.0 §6.2.5），`T_econ` 写死 5 不再可整定。

### 2.4.2 两档窗口

| 档 | 扫描窗口 | 综合区间 |
|---|---|---|
| **快速性档** | 第 1 ~ T_fast 分钟 | `[L_fast, H_fast]` |
| **经济性档** | 第 T_fast+1 ~ T_econ 分钟 | `[L_econ, H_econ]` |

> 两档窗口**无缝拼接**覆盖 `[1, T_econ] = [1, 5]`：`[1, T_fast] ∪ [T_fast+1, 5] = [1, 5]`——任何 `T_fast` 整定值下**无空档、无重叠**，不存在"调小 T_fast 后中间分钟脱离考核"的空隙（2026-08-19 显式化注：正文原只写"两档不重叠"，全覆盖性质此前需从本表推导，现钉死）。

### 2.4.3 判定逻辑（两档平行考察，互不隶属）

> **模型变更（2026-08-13）**：两档改为**平行考察**——快速性档和经济性档是两个**并列的独立考核项**（贴合附件6 把「调节快速性考核」「调节经济性考核」列为两个独立考核项），各自独立判、互不依赖，各出各的合格率、各算各的罚款。**旧模型是串联 fall-through（短窗没夹住才进长窗），已废弃。**

两档**并行**各判一次（不串行、不 fall-through）：

```
快速性档：V_target ∈ [L_fast, H_fast]？  → 快速性 QUALIFIED / PENALIZED
经济性档：V_target ∈ [L_econ, H_econ]？  → 经济性 QUALIFIED / PENALIZED
（两档判定彼此独立，互不影响；某档数据无效 L>H → 该档 invalidTiers，不出结论）
```

- 一条指令可能「快速性合格 + 经济性不合格」「两档都合格」「两档都不合格」等组合，都合法。
- **免考是档级应用**：某档 `PENALIZED` 时，单独看该档是否免考（阶段三读 `yx501`，逐档应用、结论不跨档）。

**图示**（两路并行，从 t₀ 出发分叉）：
```
指令 t₀、目标 V_target（解码成功后）
 │
 ├─→【快速性窗 [1, T_fast]】综合区间 [L_fast, H_fast]
 │       V_target ∈ 此区间?
 │        ├ 是 → 快速性 QUALIFIED
 │        └ 否 → 快速性 PENALIZED（阶段三读 yx501 决定免考与否）
 │
 └─→【经济性窗 [T_fast+1, T_econ]】综合区间 [L_econ, H_econ]
         V_target ∈ 此区间?
          ├ 是 → 经济性 QUALIFIED
          └ 否 → 经济性 PENALIZED（同上，逐档免考）

（两条路径并行、各自收尾；互不隶属、不 fall-through）
```

## 2.5 输出契约（v5.0 版，取代 4_1 三态状态机）

judge 的输出是 **sealed 类型 `RegulationOutcome`**（4_1 的三态/`EXEMPT` 状态机已废弃，历史推演存档于 4_1 §2.5）：

```
RegulationOutcome = Judged{fast: VERDICT?, econ: VERDICT?, completeness, invalidTiers}
                  | Undecodable{reason}
```

| 分量 | 语义 |
|---|---|
| `VERDICT` | 两态：`QUALIFIED` / `PENALIZED`——**不含 `EXEMPT`**（免考是阶段三后置应用） |
| `VERDICT?` 可空 | 该档 ∈ `invalidTiers` 时对应 VERDICT **必为空**；**不变式「档 VERDICT 为空 ⟺ 该档 ∈ invalidTiers」构造期强制**（2026-08-19 拍板：非空枚举装不下"不可判"，可空性让消费方类型层面读不到无效档结论） |
| `invalidTiers` | **按档无效标记**（⊆ {fast, econ}）——承载"**该档不可判**"的采集侧异常，两种成因：**S16 `L>H` 数据异常**（解码成功后窗口聚合发现）与**该档窗口整档全缺**（S14 情形，2026-08-19 交叉核对补全——否则不变式下全缺档无合法落点）；该档不判、记日志；**不进 `Undecodable`**（2026-08-19 Leo 拍板：①管线阶段对位——解码在取 V_target 之前、档异常在窗口聚合之后；②归因纯净——undecodable 归因口径保持"解码失败"即编码侧问题；③按档粒度对齐现象；整档全缺与 L>H 同族同理） |
| `completeness` | 窗口完整度（有数据的分钟占比）——**如实上报，不处置** |
| `Undecodable{reason}` | **「判不了」信号，非第三判定态**——解码失败带原因分类：`循环码非法` / `缺t₀电压` / `编码脏写`；处置归策略层（§2.9） |

- judge **不做任何处置决策**（不吞信息、不自作主张）——缺多少、为什么解不出来，如实报告；"怎么记账"外部化到参数化策略层。
- stub 期（搁置轨）：`StubRegulationJudge` 确定性输出（按输入 hash 或固定全 QUALIFIED，带 `stub=true`，**禁随机**）。

## 2.7 调节合格率统计（两档平行 · 附件6 原始分母）

> **口径拍板（Leo 2026-08-19）**：分母 = **发令总次数**（附件6 §二 原始口径「执行合格点数 ÷ 发令次数」），**取代剔除法**——免考不再剔除分母。两档**分母相同**（同一发令总次数）、分子各异（各档合格点数）。
>
> **模型基线（2026-08-13）不变**：两档各自独立算合格率与罚款额，不合并成单一合格率。

```
# —— 快速性档 ——
快速性合格率 = 快速性合格点数 / 发令总次数 × 100%
快速性缺额   = max(0, 100% − 快速性合格率)
快速性罚款   = 快速性缺额百分点 × 额定容量 × 0.02 分/万千瓦

# —— 经济性档（分母同快速性档 = 发令总次数）——
经济性合格率 = 经济性合格点数 / 发令总次数 × 100%
经济性缺额   = max(0, 100% − 经济性合格率)
经济性罚款   = 经济性缺额百分点 × 额定容量 × 0.02 分/万千瓦

# —— 总览（两个并列结果，不合并）——
调节合格率：分别报告「快速性合格率」和「经济性合格率」
调节罚款   = 快速性罚款 + 经济性罚款
```

- **免考点**：不进分子（非合格）、**进分母**（是发令）——⚠️ **罚款衔接待 Leo 确认**（推荐读法：罚金缺额剔除免考点，`罚款缺额 = 非免考不合格点数 ÷ 发令次数`，"免于考核"落在罚金层、披露合格率仍按全量分母——否则免考点拖低合格率又产生罚金，与免考条款自相矛盾）。免考点识别 = 阶段三后置读 `yx501`（PENALIZED ∧ yx501=1，逐档）。拍板时须**一并明确披露完整性**（2026-08-19 评审补）：推荐方向下「披露合格率」（全量分母）与「罚款缺额」（剔免考）是**两条独立计算链路、不能互相推导**——拿合格率倒推罚款会对不上；对外报表与流程图须显式标注"两个独立指标"，防"口径不一致 / 选择性计算"质疑。
- **「两档分母独立」表述作废**（2026-08-19 随拍板）：原剔除法下"两档有效指令数不一定相等"不再适用——新口径分母恒为发令总次数，两档差异只在分子。
- **数据不可用指令**（`Undecodable` / `invalidTiers` / 缺数据）在固定分母下自动计入并**拖低合格率**——原甲乙丙丁候选中"剔除分母"类选项与本拍板口径冲突，**候选需按新口径复核**（政策若允许对判不了类 carve-out 须重新拍板；`docs/数据不可用处理策略.md` 文头已注，2026-08-19）。

## 2.9 数据不可用处置——参数化策略层（承接 v5.0 §8.7）
