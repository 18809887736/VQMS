## 一、S2 调节合格率（指令级，三张表）

### 1.1 `vqms_regulation_cmd`（指令级明细，每条入判指令一行）

```sql
CREATE TABLE `vqms_regulation_cmd` (
  `id`                  bigint(20)   NOT NULL AUTO_INCREMENT COMMENT '主键',
  `stat_date`           date         NOT NULL                COMMENT '统计归属日（t₀ 所在日，北京历法）',
  `warn_time`           varchar(255) NOT NULL                COMMENT '指令时间原文（对齐 ledger，忠实摘录）',
  `millisecond`         varchar(255) DEFAULT NULL            COMMENT '毫秒原文',
  `obj_num`             bigint(20)   DEFAULT NULL            COMMENT '对象编号',
  `obj_num_uk`          bigint(20)   GENERATED ALWAYS AS (coalesce(obj_num, -1)) STORED COMMENT 'uk 归一生成列',
  `algorithm_id`        varchar(16)  NOT NULL                COMMENT '判定算法注册 ID（V1_0/STUB，§8.8.5 审计列）【决策④】',
  `t_fast_snapshot`     int          NOT NULL                COMMENT '判定时 t_fast 快照（跨整定期重算可复现）【关联决策②】',
  `fast_state`          varchar(16)  NOT NULL                COMMENT '快速档最终记账：QUALIFIED/PENALIZED/EXEMPTED/INVALID（FinalTierState）',
  `econ_state`          varchar(16)  NOT NULL                COMMENT '经济档最终记账（同上，两档独立）',
  `completeness`        decimal(5,4) NOT NULL                COMMENT '窗口完整度 [0,1]（judge 如实上报原值）',
  `invalid_tiers`       varchar(16)  DEFAULT NULL            COMMENT 'judge 原始按档无效标记：FAST/ECON/FAST,ECON/NULL（成因粒度，区别于 state=INVALID）',
  `undecodable_reason`  varchar(32)  DEFAULT NULL            COMMENT '解码失败归因：CYCLE_CODE_INVALID/MISSING_T0_VOLTAGE/CORRUPTED_ENCODING；NULL=解码成功',
  `yx501_sampled`       tinyint(1)   DEFAULT NULL            COMMENT '免考旗采样值 0/1；NULL=未采样（Undecodable 指令无 Judged 不走免考）',
  `disposition`         varchar(32)  DEFAULT NULL            COMMENT '策略处置桶（Disposition 四值）；NULL=策略未生效（选套前）【决策①⑥】',
  `fetched_at`          datetime     DEFAULT CURRENT_TIMESTAMP COMMENT '写入时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_cmd_result` (`warn_time`, `millisecond`, `obj_num_uk`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci COMMENT='VQMS 调节合格率指令级明细（判定+免考+策略处置结果）';
```

要点：uk 镜像 D8 生成列方案（coalesce 防 NULL 旁路，结构性幂等，重抓/重跑不产生重复行）；`warn_time/millisecond` 与源表同宽 varchar(255)（D8 教训：收窄会在 insert ignore 下静默截断造假碰撞）。

### 1.2 `vqms_regulation_daily` / `_monthly` / `_yearly`（rollup，同构）

```sql
CREATE TABLE `vqms_regulation_daily` (
  `stat_date`          date         NOT NULL COMMENT '统计日',
  `total_cmds`         int          NOT NULL DEFAULT 0 COMMENT '发令总次数=分母（含 undecodable/invalid——固定分母拍板口径）',
  `qualified_fast`     int          NOT NULL DEFAULT 0,
  `penalized_fast`     int          NOT NULL DEFAULT 0,
  `exempted_fast`      int          NOT NULL DEFAULT 0,
  `invalid_fast`       int          NOT NULL DEFAULT 0,
  `qualified_econ`     int          NOT NULL DEFAULT 0,
  `penalized_econ`     int          NOT NULL DEFAULT 0,
  `exempted_econ`      int          NOT NULL DEFAULT 0,
  `invalid_econ`       int          NOT NULL DEFAULT 0,
  `undecodable_count`  int          NOT NULL DEFAULT 0 COMMENT '解码失败指令数（归因分布看明细表）',
  `pended_count`       int          NOT NULL DEFAULT 0 COMMENT '丁档挂起标记数【决策①呈现列】',
  `excluded_count`     int          NOT NULL DEFAULT 0 COMMENT '乙档剔除计数——仅披露用；现行拍板=不剔分母，若 S5 改口径再启用分母扣减【决策①呈现列】',
  `completeness_sum`   decimal(10,4) NOT NULL DEFAULT 0 COMMENT '完整度求和（均值=本列/total_cmds，还原加权——不存平均率）',
  -- monthly/yearly 版本把 stat_date 换成 stat_month char(7) / stat_year smallint，其余同构
  PRIMARY KEY (`stat_date`)
) ENGINE=InnoDB ... COMMENT='VQMS 调节合格率日汇总';
```

rollup SQL：`INSERT...SELECT...SUM(各计数) GROUP BY 周期 ON DUPLICATE KEY UPDATE` 经典写法；率（披露合格率/罚款缺额两链）一律查询层或写回快照由计数重算，**表中不存平均过的率**。两链结构（罚款缺额剔免考与否）属待拍板项——counts 已够两条链各自推导，DDL 不预支结论。

## 二、S3 投运率（时间记账，两张表 + 一个新缺口）

### 2.1 `vqms_runtime_daily` / `_monthly` / `_yearly`

```sql
CREATE TABLE `vqms_runtime_daily` (
  `stat_date`            date         NOT NULL COMMENT '统计日',
  `in_service_min`       int          NOT NULL DEFAULT 0 COMMENT '投运分钟',
  `exit_grid_min`        int          NOT NULL DEFAULT 0 COMMENT '电网原因退出分钟（免责，出分母）',
  `exit_nongrid_min`     int          NOT NULL DEFAULT 0 COMMENT '非电网退出分钟（扣罚，在分母）',
  `offline_min`          int          NOT NULL DEFAULT 0 COMMENT '未并网分钟（不计任何账，透传核对用）',
  `rated_capacity_kw`    decimal(12,3) DEFAULT NULL COMMENT '计算时额定容量快照（kW）【开放点⑤】',
  `rate_pct`             decimal(6,3) DEFAULT NULL COMMENT '投运率快照（纯函数算出写回；零并网分钟=NULL 语义）',
  `shortfall_pct`        decimal(6,3) DEFAULT NULL,
  `penalty_score`        decimal(12,3) DEFAULT NULL,
  -- monthly/yearly 同构换周期键
  PRIMARY KEY (`stat_date`)
) ENGINE=InnoDB ... COMMENT='VQMS AVC 投运率日记账';
```

rollup 对四个分钟计数求和；月/年行的率快照由**合计分钟重算**（RuntimeStatistics 纯函数），非日均值的平均。零并网分钟约定（率/缺额/罚款全 0、报表 NULL 呈现）沿用 S3 报告声明的口径——rate_pct 存 NULL 区分「真 0%」与「无可考核基数」。

## 三、四项设计时决策——推荐选项（§12.2 S2 行登记）

| # | 决策 | 推荐 | 理由 |
|---|---|---|---|
| ① | 策略丁档标记列 | **不加独立布尔列**——明细 `disposition` 列存 Disposition 原值（四桶通吃），rollup 加 `pended_count`/`excluded_count` 两个披露计数 | 一列承载四桶比单为丁设列更通用；乙/丁组合候选（双处置）若拍板再扩（§8.7 已登记扩表达力路线） |
| ② | `t_fast` 默认值 | 维持种子 **4** 不动；明细表加 `t_fast_snapshot` 快照列 | 默认值本就「待现场确认」（§6.2.5）；快照使跨整定期数字可复现可审计，改默认值不影响历史行 |
| ③ | invalidTiers·免考汇总呈现 | rollup 存**计数**（exempted/invalid × 两档 + undecodable_count），前端呈现层组合 | 计数是唯一 rollup 安全形态；呈现（百分比、标注）归 UI，避免表结构锁死报表样式 |
| ④ | `algorithm_id` 及跨切换 rollup 取值 | 明细行必带 `algorithm_id`；rollup 行同列，周期内单一算法=该 ID、**混合='MIXED'**，显式重算后自然归一 | 「当时哪个算法算的」逐行可答（§8.8.5 审计落点）；MIXED 显式暴露混算周期，防静默混数字 |

## 四、新增开放点（本轮设计发现，须拍板）

| # | 问题 | 推荐选项 |
|---|---|---|
| ⑤ | **额定容量无载体**——调节罚款与投运率罚款都要 `rated_capacity_kw`，现有六张管理表均无此列（`vqms_judge_param.param_value` 是 int 装不下小数） | `vqms_busbar_group` 加 `rated_capacity_kw decimal(12,3)`（组=配置单元，厂级口径取组和或直配主组）；或独立一行 sys_config。前者结构化、可随 500kV 组补录 |
| ⑥ | 选套前 `disposition` 列语义 | 可空 + NULL=「策略未生效」；统计消费端遇 NULL 按「只记不判」呈现（横幅口径同 §8.7 页面三态）。不用默认值假装选了甲 |
| ⑦ | 明细表 uk 方案 | 镜像 D8 生成列 coalesce 方案（上文 DDL 已按此写）——如无异议此项不算决策 |
