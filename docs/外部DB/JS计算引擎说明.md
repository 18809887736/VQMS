# 对端 AVC 计算引擎说明（JS_DATA / GS_DATA）

> 数据来源：`QHeatAvcRtdb`（SQLite，AVC 装置配置库）的 5 张表：`GS_DATA` / `JS_DATA` / `JS_DATA_STEP` / `JS_DATA_STEP_VAR` / `JS_DATA_VAR_TYPE`（存档于 `docs/外部DB/JS/`）。
> 一句话：对端 AVC 自带一个**配置驱动的计算图引擎**，周期性对点位做算术/逻辑/聚合运算，结果作为"虚拟点"和原始遥测一起写进 `yc_history` / `yx_history`。VQMS **消费结果、不重建引擎**。

---

## 一、四张表 = 一个计算节点的完整定义

每个"计算量"（如"3#机组投退"）由四张表协同定义：

| 表 | 角色 | 关键字段 |
|---|---|---|
| `JS_DATA` | **节点头**：算什么、结果给谁 | `js_code`(名) / `result_type`(1=yc, 2=yx) / `relate_num`(输出点号) |
| `JS_DATA_STEP` | **算子**：用什么运算 | `gs_num`(算子号→查 GS_DATA) / `var_count`(输入个数) |
| `JS_DATA_STEP_VAR` | **输入**：算哪些点 | `var_type`(0常量/1yc/2yx/3电度/4步骤) / `var_num`(点号) |
| `JS_DATA_VAR_TYPE` | 字典：变量类型 | 0常量 / 1遥测 / 2遥信 / 3电度 / 4步骤 |
| `GS_DATA` | 字典：45 种算子 | `gs_num` → 运算语义 |

**求值流程**（对端周期执行）：
1. 按 `JS_DATA_STEP_VAR` 取各输入点当前值（yc/yx/常量/另一步骤结果）
2. 按 `JS_DATA_STEP.gs_num` 对应的算子运算
3. 结果按 `result_type` 写到 `relate_num` 点号
4. 该虚拟点与原始遥测**一起存进 `yc_history` / `yx_history`**

---

## 二、算子分类（GS_DATA 的 45 个）

| 类别 | 算子（gs_num） |
|---|---|
| **算术** | 1 累加  2 累乘  3 符号取反  4 倒数 |
| **逻辑** | 5 与  6 或  7 非  8 同或  9 异或  10 大于  11 小于  12 相等  13 ≥  14 ≤ |
| **三角** | 15~32  sin/cos/tg/ctg 及反函数、角度变体 |
| **控制** | 33 IfElse(X?A:B)  34 当前时间  35~40 年/月/日/时/分/秒 |
| **聚合** | 41 查表(TableNum, KeyValue)  42 Max(YcNum, 秒)  43 Min  44 Average |
| **特殊** | 0 内蒙古计划电压（2 变量：当前母线电压 + 增量命令） |

- `var_count=0` 表示**变参**（累加/或，任意个输入）。
- 固定值表示该算子要求的输入数（非=1、同或=2、IfElse=3）。

## 三、关键机制

### 1. 结果落到"虚拟点号"

`result_type` + `relate_num` 决定结果去向：
- `result_type=1` → 写成 **yc 点**（连续值：无功、电压、增量…）
- `result_type=2` → 写成 **yx 点**（0/1：投退、闭锁、越限…）

这些虚拟点（yc11、yx210、yx3001…）**和原始遥测同表存储**，VQMS 按点号读历史表即可，分不清也无需分清"实测"还是"算出来"。

### 2. var_type 支持链式组合

```
0=常量   1=遥测yc   2=遥信yx   3=电度   4=步骤(引用另一JS的结果)
```
`var_type=4` 让一个 JS 的输出可作另一个 JS 的输入，构成计算图。

### 3. 点号段约定（从数据归纳）

| 点号段 | 设备/含义 | 实例 |
|---|---|---|
| 1xx / 2xx | 1#机（3#机）原始点 + 合成点 | yx201 主断 / 202 刀闸 / 204,205 → 投退 yx210 |
| 3xx / 4xx | 2#机（4#机）原始点 + 合成点 | yx301/302/304/305 → 投退 yx310 |
| 1xxx | 越限 / 转发 / 计划合成点 | yx1101 越限 / 1103 总闭锁 / yc1001 / yc1007 增量 |
| 2xxx | 闭锁总信号 / 远方就地 | yx3001~3009 闭锁 / yx2003 远方就地 |
| yc217/317 | 机组无功 | 1#机 / 2#机 |
| yc11 / 17 | 母线总无功 | 正母 / 副母 |

## 四、三层闭锁抽象（真实数据呈现的分层组合）

```
原始接点 yx211~216, 230~233
   │ js9/10  OR
   ▼
总闭锁 yx1103(3#) / yx1104(4#)
   │ js5/6   OR(+总闭锁+其他)
   ▼
增磁闭锁 yx208 / 减磁闭锁 yx209
   │ js11/12 OR(增磁+减磁+总闭锁)
   ▼
越限 yx1101(3#) / yx1102(4#)
   │ js101~109 OR(母线层/机组层各分散点)
   ▼
母线 / 机组 闭锁总信号 yx3001~3009
```

越往上越抽象：分散的原始接点逐层 OR 成"机组级""母线级"总信号。

## 五、典型应用模式（全部从真实数据反推）

| 模式 | 算子 | 实例（库里现成） |
|---|---|---|
| **投退 = AND(断路器, 刀闸)** | gs5 与 | `yx210 = yx204 AND yx205`（3#机）；`yx310 = yx304 AND yx305`（4#机） |
| **闭锁总 = OR(分散接点)** | gs6 或 | `yx3001 = OR(yx4,5,6,9,10,11,14,15,16,17,20,21,22,25)`（14 个） |
| **总无功 = SUM(各机组)** | gs1 累加 | `yc11 = yc217 + yc317`（= 1#机 + 2#机无功） |
| **越限 = OR(各类闭锁)** | gs6 或 | `yx1101 = OR(yx208, yx209, yx1103)` |
| **远方就地合并 = OR** | gs6 或 | `yx2003 = OR(yx12, yx23)` |
| **增量 = 电压 + 命令** | gs1 累加(带负值) | `yc1007 = yc1 + yc1005`（"220KV减210"）；`yc1008 = yc1 + yc1006`（"500KV减500"） |

> 最后一行关键：**`yc1007` / `yc1008` 就是对端自己算的电压增量指令值**，呼应 `warn_info` 里的"220KV减210 / 500KV减500"和增量编码（见 [数据源头（草稿）.md](../数据源头（草稿）.md) 增量值解码）。

### 新增派生点：正母 / 副母单元信息 yc（按母线组织）

依据 `BUS_GEN_LINK_LOGIC_DEV` 的 4 条机组-母线连接关系（1号机–正母 yx201,202 / 1号机–副母 yx201,203 / 2号机–正母 yx301,302 / 2号机–副母 yx301,303），**按母线**输出两个 relate_num(yc)：正母单元信息、副母单元信息。每个值打包"该母线是否带电 + 该母线上并网机组数"。SQL 定义见 [JS/JS_并网与母线号.sql](JS/JS_并网与母线号.sql)。

| 点号 | 类型 | 名称 | 编码 | 取值 | VQMS 用途 |
|---|---|---|---|---|---|
| `yc511` | yc | 正母单元信息 | 带电(1/0)×10 + 并网机组数(0/1/2) | `0`=空母线 / `11`=1台机 / `12`=2台机 | 按母线分组判定 + 母线带电 |
| `yc512` | yc | 副母单元信息 | 同上 | 同上 | 按母线分组判定 + 母线带电 |

> 母线号隐含在点号里：yc511=正母(0)、yc512=副母(1)，无需再编码进值。

**解码**：带电 = `值 ÷ 10`（≥1 即带电）；并网机组数 = `值 % 10`。

**算法分解**（正母 yc511，js=220，6 步；副母 js=221 同构，把 yx202/302 换成 yx203/303）：
```
step0  1号正母连 = yx201 AND yx202
step1  2号正母连 = yx301 AND yx302
step2  正母机数   = step0 + step1          ← 并网机组数(0/1/2)
step3  正母带电   = step0 OR step1         ← 是否带电(1/0)
step4  带电x10    = step3 × 常量10
step5  正母编码   = step4 + step2          → yc511 (0/11/12)
```

> **电厂并网**（投运率分母）= `yc511 ≥ 10` OR `yc512 ≥ 10`（任一母线带电）。
> **主母线判定**：可直接用 `BUSBAR.IsMainBusBar`（东母=1）；或用本节的带电母线号。

## 八、VQMS 操作结论

1. **VQMS 不执行 JS 引擎**——对端已周期性算好，结果落到虚拟点号进历史表。
2. **把四张表当数据字典**：查"点号 N 是什么、怎么算的"，真值直接按点号读 `yc_history` / `yx_history`。
3. **建 `yc_point_map` 时**，把第六节所有虚拟点照 `JS_DATA` 语义填入 `point_name` / `point_type` / `unit`。
4. **能读计算点的，一律读计算点**——尤其投退/闭锁这种考核相关量，对端判定才是权威，VQMS 自行复算易与之发散。
5. **核实前提**：这些虚拟点确实被存进了 `yc_history` / `yx_history`（取决于 `AVC_INFO.isSaveHistory=1`，库内为开）。落地前抽查历史表是否含点号 210/3001/11 等。
