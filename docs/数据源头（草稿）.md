## 1. 调度的指令（发令事件）

电压或无功指令。本项目**暂时只考虑电压指令**，无功指令留有接口以便后续开发。

**来源：`warn_info` 表**（注：**不从 `his_curve_sv.plan_SV` 获取**）

| 字段        | 含义             | 备注               |
| ----------- | ---------------- | ------------------ |
| `warn_type` | 通常为 `5`       | 现场人员整定       |
| `obj_num`   | 对象编号         | 现场人员整定       |
| `warn_info` | 目标值 或 增量值 | 文本内含数值，见下 |

指令有两种形态（`warn_info` 文本示例）：

- **增量值**：`收到远方遥调执行指令:辽宁母线电压增量指令编码值处理,2202.`
  - 编码 `2202` 解码（左起 4 位）：
    - **第 1 位 `2`** —— 方向：`2` = 增加，`1` = 减少
    - **第 2 位 `2`** —— 循环码（具体含义待确认）
    - **第 3–4 位 `02`** —— 增量幅值，每单位 100V → `02` = **200V**
  - ⇒ `2202` = **电压增加 200V**
  - 💡 **增量值 + 当前实时母线电压 = 绝对目标值**（与"目标值"形态殊途同归）。例：当前电压 `234.25 kV` + `0.2 kV`（200V）= 目标 `234.45 kV`。两种指令形态最终都产出一个绝对目标电压。
- **目标值**：`收到远方遥调执行指令:主省220KV目标值,22315.` —— 代表 **223.15 kV**
- 其他类型：预留

> 一条指令由（`warn_type`、`obj_num`、目标值或增量值）表征。本项目给个初始值后，保留 **CRUD 的读取、更新**功能。

# 四、数据缺口核对（对照 [AVC考核核心算法_草稿4_1.md](AVC考核核心算法_草稿4_1.md)）

把核心算法每一步需要的数据，对照上文一~三节现有数据源，结果：调节合格率主判定够用，但投运率 / 免考 / 考核量存在 4 个缺口。

| 算法步骤 | 需要的数据 | 现有数据源 | 结论 |
|---|---|---|---|
| 调节合格·解码目标电压（目标值形态） | `warn_info.warn_info` 文本 | ✅ 有（`warn_type=5`） | 够 |

| 调节合格·按主母线分组 | 主母线号 | ✅ 有（yc_history 主母线号点） | 够 |

| **调节合格·免考判定** | 每台 AVC 无功设备实测 Q + 双向极限 (Q_max_发, Q_max_吸) | 📨 **接口待对端**：`yx501`（全厂一个，二态 0/1） | **接口已定** |

## 缺口说明

- **缺口① 并网运行信号**（投运率分母）：✅ **已补**。由对端 JS 引擎算好的 `yc511`（正母单元信息）/`yc512`（副母单元信息）提供（见 [JS_并网与母线号.sql](外部DB/JS/JS_并网与母线号.sql)、[JS计算引擎说明.md](外部DB/JS计算引擎说明.md)）。编码 = 带电(1/0)×10 + 并网机组数(0/1/2)；**电厂并网 = `yc511≥10` OR `yc512≥10`**（任一母线带电即并网运行）。该值由对端据 `BUS_GEN_LINK_LOGIC_DEV` 的机组-母线开关拓扑（yx201/202/203、yx301/302/303）周期性求值得出，VQMS 直接读结果即可。
- **缺口② AVC 退出原因**（投运率免责）：📨 **接口已定，待对端实现**。复杂运算（把 9 个 `lock_*_yx_num` + yx3001~3009 闭锁信号按"电网 vs 非电网"归类）**甩给对端 JS 引擎做**，VQMS 只接收**2 个结论值**（分母线，因退出按母线发生）：
  - `yc521` 正母退出原因、`yc522` 副母退出原因
  - 三态编码：`0`=未退出 / `1`=电网原因（免责）/ `2`=非电网原因（扣罚）
  - VQMS 侧判定：`0`→投运分钟；`1`→从分母扣除；`2`→计入惩罚性退出
  - 对端职责：按现场/调度确认的归类规则配 JS（哪类闭锁=电网/非电网）；VQMS 不掺和归类逻辑。
- **缺口③ 设备级无功 / 免考判定**（调节合格率免考）：📨 **接口已定，待对端实现**。免考的逐设备复杂运算（每台机实测 Q vs 随 P 变的 P_QLimit 极限、方向匹配、全部顶满汇总）**全部甩给对端 JS 引擎做**，VQMS 只接收**1 个结论值**（全厂一个）：
  - `yx501` 免考标志：`1`=该时段全部 AVC 闭环无功设备已正确方向顶满（**免考**）；`0`=未顶满（不免考）
  - VQMS 侧判定：`调节不合格 AND yx501=1` → 执行不合格-免考（不计率不计罚）；否则 → 执行不合格-非免考（罚）
  - 对端职责：用 `GENERATOR.qYcNum`(yc217/317) + `pYcNum`(yc216/316) + `GENERATOR_P_QLimit` 查表 + 方向匹配 + 全设备 AND，配成 JS 输出 yx501；VQMS 彻底从"设备清单/能力曲线维护"解脱。
  - 说明：发电机部分对端数据齐全（[GENERATOR](外部DB/QHeatAvcRtdb.md) + P_QLimit）；若 AVC 还控其他无功设备（SVC/电容等），对端算 yx501 时自行纳入 AND，VQMS 只信结论。
- **缺口④ 额定容量**（考核量）：✅ **有数据**，是**定值**。并网主体全厂总额定 = `Σ GENERATOR.ratingPPower` = 300000 + 300000 = **600000 kW**（2 台 300MW 机组）。VQMS 处理方式：给个**初始值**（取自配置库 Σ）后，建配置项**保留 CRUD 的读取、更新**功能（运行人员可在系统里改，如增容改造后更新），不写死代码。考核量公式：`缺额百分点 × 额定容量(万千瓦) × 0.02`。

## 结论

- **调节合格率主判定**（high/low 包络判目标电压）：**数据够用** ✅
- **投运率**：缺口① ✅ **已补**（yc511/yc512）；缺口② 📨 **接口已定**（yc521/yc522，待对端实现）→ 分母可算、免责靠对端结论值
- **免考**：缺口③ 📨 **接口已定**（yx501，待对端实现）→ VQMS 读 1 个结论值即可判，复杂运算全在对端
- **考核量**：缺口④ ✅ **已补**（定值 600000 kW，VQMS 给初始值 + CRUD 读写）

> **架构原则**：缺口②③的复杂运算（闭锁归类、逐设备 Q vs 极限）**甩给对端 JS 引擎**，VQMS 只收固定个数的结论值（②收 2 个、③收 1 个），VQMS 侧零计算。点号 yc521/522、yx501 为建议空号，现场导入若冲突可改，接口契约（取值含义）不变。
