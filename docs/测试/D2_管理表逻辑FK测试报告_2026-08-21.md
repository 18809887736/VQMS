## 四、架构要点记录

### 4.1 逻辑 FK 设计哲学

v5.0 §6.2 明确："六表之间不建物理外键（跨库 + 与 RuoYi 风格一致）……一致性靠应用层"。因此:

- **Mapper 层**: 不校验，直接写入——与 DB 行为一致
- **Service 层**: 插入/更新前做存在性校验，抛出 `IllegalArgumentException` / `IllegalStateException`
- **测试断言**: 验证 Mapper 层面接受非法 FK（因为确实没有 DB 约束），同时验证引用关系可查询

### 4.2 threshold 生效区间闭合

新增阈值时，自动将同 busbar_num 的当前有效记录（effective_to IS NULL）的 effective_to 设为昨天——保证同一母线不同时存在两条重叠生效区间。此操作为事务内执行，见 `VqmsBusbarThresholdService.insert()`。

### 4.3 数据库连接

- 主库（管理表）: `jdbc:mysql://10.0.0.9:13306/ry_vqms`
- 凭据: 环境变量 `MYSQL_ROOT_PASSWORD`（默认从 shell 脚本读取）
- 测试使用 Spring `SqlSessionFactoryBean` + `DriverManagerDataSource`，与生产配置隔离
