## 二、设计与拍板记录

### 2.1 NULL 去重键拍板（测试方案 §4.7 授权 D8 起草定）

选**候选②**（评审倾向）：`uk_cmd` 改经 **STORED 生成列** `coalesce` 归一——`millisecond_uk = coalesce(millisecond,'')`、`obj_num_uk = coalesce(obj_num,-1)`（-1 不与真实对象编号撞，现场编号恒正）。重复抓取由 DB 层结构性拦截，应用层去重代码为零、无 check-then-insert TOCTOU 竞态；幂等入口 = 单条 `insert ignore` 批插。**`millisecond` 同为可空键列，一并归一**——只堵 obj_num 会留下同构 NULL 旁路（1 行 DDL 的事）。

### 2.2 millisecond 列宽与源同宽（对抗验证吸收，supersede 初版规约 varchar(8)）

外部源 `warn_info.millisecond` 为 varchar(255) 无约束（`save_time` varchar(255) 同类病灶有先例），三步闸门只校 `warn_time`。若收窄 varchar(8)：`insert ignore` 会把超宽脏值的 1406 错误降级 warning **静默截断入库**，且截断值进 `millisecond_uk` 参与唯一键——前 8 字符相同的两条真实指令被判同键，第二条被当「重复」静默丢弃（日志还记成重复跳过）。这打在流水账唯一的存在理由上（§8.6 搁置期从原文重算，「先记后定不吃亏」）。修复 = 列宽对齐源表 varchar(255)（`sql/vqms.sql` / `sql/5.0/vqms_tables.sql` / 迁移脚本三处同步；uk 键长 32×4+255×4+8=1156 字节 < 3072 InnoDB 上限，无代价），并补超宽毫秒保真回归用例。

### 2.3 架构落位

- `VqmsCommandLedgerService`（management/service）：经 `SourceReader.readWarn(…, 5L)`（SLAVE + D4 闸门）→ 原文字段一一摘录 → `insertIgnoreBatch`。**不做任何解码/判定**（只记不判，§8.6）；**不得加 @Transactional**（事务钉主库会吞掉 readWarn 的 SLAVE 切换——javadoc 已声明）。
- `VqmsCommandLedgerMapper`：只增表无 update；`deleteByWarnTimeRange` 仅供测试行级自清理（javadoc 声明）。
- 抓取编排（定时触发）随 S4 Quartz，不在 D8——当前唯一调用方是 IT。
- 生成列由 DB 维护，domain/mapper/insert 列清单全程不读写。

## 三、断言清单（D8CommandLedgerIT 5 用例）

| 用例 | 断言 |
|---|---|
| **全量入账 + 逐字段一致** | 外部源全量 `warn_type=5`（raw SQL 快照，不经闸门）与账内行数相等；双向键集合比对无多余/无遗漏/无重复；`warn_type`/`warn_content` 逐字段一致（warn_time/millisecond/obj_num 即键本身） |
| **uk 幂等（§4.7 原文形态「重复抓取两遍」）** | 用例内第一抓自足预热（空库/独立测试库/任意方法序成立），第二抓新增 0、总行数不变 |
| **NULL 键 DB 层兜底** | `obj_num=NULL`+`millisecond=NULL` 哨兵行同批两条只落 1 行、跨批 insert ignore 新增 0；**不带 ignore 的原生 INSERT 必炸唯一键冲突**（约束存在的直接证明，非应用层逻辑）；生成列归一值 `''`/`-1` 实证 |
| **超宽毫秒保真（对抗验证回归锁）** | 9 字符 millisecond 原样入账（窄列时代会静默截成 8 字符） |
| **无判定结论列** | `information_schema.columns` 列集合**精确匹配**（原始摘录 7 列 + 幂等生成列 2 列，比集合不比序）——多出任何列即失败 |

行级自清理：仅哨兵行（warn_time `2099-*`，远离场景日）用例内 try/finally 自删；场景入账行是外部源合成数据的忠实摘录、重抓幂等，留库即 D8 功能本体。

### 5.1 已吸收（本轮修复）

| 发现 | 严重度 | 命中视角 | 修复 |
|---|---|---|---|
| **millisecond varchar(8) 窄于源 varchar(255) + insert ignore = 无报警截断/假碰撞丢行通道**——闸门只校 warn_time，超宽脏值被 ignore 静默截断，截断值进 uk 致前 8 字符相同的两条指令并档丢行，日志记成「重复跳过」；打在「忠实原文底账」的存在理由上（初版规约 varchar(8) 系规格内在缺口，实现忠于规格） | major（三视角独立命中） | correctness / spec / simplicity | 列宽对齐源表 varchar(255)（三处 DDL 同步 + 线上补 modify + 迁移脚本终态化）；IT 补 9 字符毫秒保真回归锁（§三 用例 4） |
| **幂等用例不自足**——只抓一遍断言 0，隐式依赖 fullWindow 先跑/共享库残留；测试方案 §4.7 原文形态是「重复抓取**两遍**」，构成未声明偏离；转产换独立测试库 ry_vqms_test 后必假失败 | major（两视角命中） | correctness / simplicity | 按方案原文补足两遍形态：用例内第一抓自足预热（ingest 幂等，空库/任意方法序成立），第二抓断言零新增 |

### 5.2 已驳回（对抗核实不成立）

| 主张 | 驳回理由（核实要点） |
|---|---|
| 迁移在存量 NULL 键重复行上重建 uk 会炸、缺预去重步骤 | 唯一持有旧 DDL 的环境（10.0.0.9）已迁移成功且当时无重复行积累路径（抓取器 D8 当天才写、编排未上线）；MySQL 8.0+ DDL 原子化无半途状态；脚本内自动去重反而违反只增语义 |
| uk 不含 warn_type，未来放开全量告警入账（§14-8）会静默合并 | 唯一写方硬编码 warn_type=5，今天不可触发；实现与 v5.0 §6.2.6 规约逐字一致；扩展属未来拍板项 |
| deleteByWarnTimeRange（仅测试用）落在只增表的生产 mapper 是脚枪 | 生产零调用 + 接口 javadoc 双处声明；v5.0 §6.2.6 只约束数据层只增、不规定 mapper 表面形态；真实强制层在 v5.0 §11 账号权限拆分 |
| 幂等用例依赖 JUnit 方法序哈希巧合 | Jupiter 默认序确定性使当前组合恒绿；真问题（§4.7 形态偏离）已由 5.1 第二条吸收 |
| 全量入账 oracle 的 between 边界/双写假想机制 | 读回路径与快照施加同款 between（对称排除）；warn_info 无双写记载、生成器整库重建不累积重复 |

### 5.3 已知边界（声明，不修）

- `uk_cmd` 不含 `warn_type`：本账只收指令（写方硬编码 5），若 §14-8 拍板放开全量告警入账，须届时把 `warn_type` 纳入 uk（DDL 演进随该拍板）。
- `utf8mb4_general_ci` 为 PAD SPACE：millisecond 尾随空格差异在 uk 比较中不可见（`'447'` 与 `'447 '` 同键）。触发需同 warn_time 同 obj_num 且毫秒仅差尾随空格的双重巧合，未修；若未来认为相关，换 `utf8mb4_0900_ai_ci`（NO PAD）即闭合，属整表 collation 演进项。
- 场景入账行留共享库：外部源重灌（数据变化）后账内旧行不更新（只增语义），幂等只保证不重复不保证追新——真实数据接入时以 S4 编排的抓取窗口策略处理。
