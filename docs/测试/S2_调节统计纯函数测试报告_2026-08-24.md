## 二、交付物与设计要点

### 2.1 main（statistics 包新增 4 类）

| 类 | 要点 |
|---|---|
| `FinalTierState` | 免考应用后逐档记账四态 {QUALIFIED, PENALIZED, EXEMPTED, INVALID}；INVALID 双来源 = invalidTiers 档透传 + Undecodable 整指令管线合成占位 |
| `TierFinalDisposition` | 两档状态容器（record 构造期拒 null）；`allInvalid()` 工厂供管线合成 Undecodable 占位 |
| `ExemptionApplier` | `apply(Judged, yx501∈{0,1}) → TierFinalDisposition`——PENALIZED∧旗=1→EXEMPTED、旗=0→计罚、QUALIFIED/invalidTiers 档透传；**类型堵**：签名只收 `Judged`，`Undecodable` 编译期进不来（其分流归 Pipeline，§5.0 既定由集成断言覆盖） |
| `RegulationStatistics` | `summarize(List<TierFinalDisposition>, ratedCapacityKw) → Summary{fast, econ, totalPenaltyScore}`——固定分母=流内指令数；披露合格率=合格/全量；罚款缺额=⚠非免考不合格/全量（推荐读法）；罚款=缺额百分点×(kW/10000)×0.02 分；空流约定返回 0 不产 NaN |

## 三、口径逐条对照（正式 v1_0 §2.7 / §5.0 矩阵）

| 口径要求 | 落点 | 断言 |
|---|---|---|
| 分母 = 发令总次数，两档同分母 | summarize 以输入流大小为分母 | handVector `totalCommands=10` 两档一致 |
| 免考点不进分子、不剔分母 | EXEMPTED 只增 exemptCount | exemptStaysInDenominator（4 免考→披露 0%、罚款 0） |
| Undecodable / invalidTiers 计入拖低合格率 | INVALID 在分母不在分子 | invalidDragsDown（1 合格+1 INVALID→披露 50% 非 100%） |
| 缺额 max(0,…) 封底 | penalized≥0 ⇒ 缺额构造性非负；空流显式 0 | 边界用例组 |
| 总罚款 = 两档相加 | Summary.totalPenaltyScore | handVector 30 分 |
| Undecodable 编译期进不了免考组件 | sealed Judged-only 签名 | 类型保证，无运行时用例（报告声明，非遗漏） |
| ⚠ 两链独立不可互推（推荐读法） | 披露链全量分母 / 罚款链剔免考 | twoChains_notDerivableFromEachOther |

## 四、偏离声明（依例明示）

1. **summarize 输入省略蓝图 `Disposition?` 半边**（v5.0 §8.8.2 写的是 `TierFinalDisposition × Disposition?`）：现行固定分母拍板下处置桶不改变统计算术（不可判一律计入分母拖低），选套落地前该字段无行为语义、只余上游已有的留痕计数（D8 流水账 / D9 策略评估调用方）；引入即死字段。选套落地需分支时扩展输入契约再补——届时丙类 COUNT_UNQUALIFIED 的映射一并定。
2. **容量参数取 kW 函数内换算万千瓦**（蓝图签名示意未及单位）：遵 CLAUDE.md 单位规约（容量存 kW）、考核单价按万千瓦计——换算收敛在函数内，调用方零换算。
3. 其余无偏离。Undecodable 分流归 Pipeline 集成断言为 §5.0 既定安排。

## 五、已知边界（声明，不修）

- **INVALID 不进罚款缺额链**：现行实现下数据不可用拖低披露合格率但**不产生罚金**——丙类「计不合格」选套落地后语义会变（届时由管线把处置映射进统计流），当前行为随两链拍板一并复核。
- **门控拦截指令是否计入分母**属管线层决策（S4 RegulationPipeline 定），summarize 只对进入统计流的指令负责。
- 分母口径正确性由调用方保证（纯函数无指令总数之外的信息源）。
