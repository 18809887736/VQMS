# VQMS 测试方案

> 文档定位：v4.0 §测试的细化与权威。配合 `docs/AVC考核核心算法_草稿.md`（算法口径）、`tools/avc-data-gen/`（合成数据 + 期望结论 oracle）、v4.0 §8/§12（算法搁置预留策略）使用。
> 状态：**规划**。L0/L2 数据驱动框架已随生成器就绪，其余层级在后端 `ruoyi-vqms` 落地时逐层补。

## 0. 核心难题与解法

**难题**：判定算法（草稿 §2）尚未定稿，怎么测？

**解法**：
1. **契约 oracle**：`tools/avc-data-gen/output/manifest.json` 把 26 个场景的期望结论（两档三态、投运率）定义成机器可读契约。判定实现（stub 或真实）必须对它全绿——这把"算法没定稿"降级成"实现可换、契约不变"。
2. **隔离快慢轨**：快轨（source 层 / 数据驱动 / 前端 / 部署）现在就能全绿；慢轨（真实判定逻辑）等草稿 §2 定稿，由 stub 占位保编译、保接口。
3. **decode 奇偶校验**：Java 判定器 vs Python `decode.py` 互相对照解码结果——打破"生成器和判定器共用同一套解码"的循环依赖（否则两边 bug 互相掩盖）。

## 1. 测试分层（金字塔）

| 层 | 名 | 被测对象 | 是否依赖算法定稿 | 触发时机 |
|---|---|---|---|---|
| **L0** | 纯工具单元 | 取整/解码/包络聚合（Python + 未来 Java） | 否（解码是契约级稳定） | 生成器改动即跑 |
| **L1** | stub 占位 | `StubRegulationJudge` 返回值、接口契约 | 否 | `ruoyi-vqms` 建起即跑 |
| **L2** | 数据驱动场景（核心） | 判定器对 26 场景的结论 vs manifest | 否（stub 期=验证管线；真实期=验证算法） | stub/真实实现都要跑 |
| **L3** | source 层集成 | 外部源只读层（varchar 取整、双写去重、排序） | 否 | source 层落地即跑 |
| **L4** | 部署 E2E | 4 容器起、API 通、前端取数 | 否 | `docker compose up` 即跑 |
| **L5** | 真实数据验证 | 读 `_qheatavchisdb` 真实数据跑判定 | 部分依赖（稳态数据全合格） | 真实数据接入后 |

慢轨 = L2 的"真实判定逻辑实现" + L5 的"越限分支"。其余全是快轨。

## 2. L0 · 纯工具单元

无外部依赖，pytest 即跑。这是整个判定链的算术地基。

### 2.1 Python 侧（已就绪，15 用例全绿）

`tools/avc-data-gen/tests/test_l0_units.py`（运行：`python -m tests.test_l0_units`）：

| 用例 | 断言 |
|---|---|
| `round_to_minute` 边界 | `:29.x` 舍、`:30.x` 进、`59:29`→当分、`59:30`→进位小时 |
| `decode` 目标值 | `22315`→223.15kV、`22500`→225.0kV |
| `decode` 增量 | `2202`@234.25→234.45、`1202`@234.25→234.05（方向位 1/2） |
| `decode` 失败 | `abc`/空/`999`（超量程）→返回 None |
| 包络聚合 | 5 分钟 `(H,L)` 列表 → `[min(L), max(H)]` |

### 2.2 Java 侧（后端落地时补）

`ruoyi-vqms` 内 `decode`/`roundToMinute`/`envelope` 的 JUnit 单元测试，**用与 2.1 相同的输入输出**——这就是 decode 奇偶校验：两边对同一组样例必须给出相同结果，任何分歧即缺陷。

## 3. L2 · 数据驱动场景（核心）

**这是整个测试体系的重中之重**——判定算法的正确性最终由它担保。

### 3.1 双轨复用同一 manifest

```
manifest.json (26 场景期望结论)
      ↑ 断言对照
  ┌───┴───────────────────────────┐
stub 期: 判定器=StubRegulationJudge   →  验证"管线通、能调通、返回结构对"
真实期: 判定器=DefaultRegulationJudge →  验证"算法算得对"
```

stub 期 manifest 全绿 ≠ 算法对（stub 返回值本就是为对齐 manifest 写的）；**真实判定实现替换后**，同一 manifest 全绿 = 算法对。契约不变、只换实现，这是搁置预留策略的测试侧体现。

### 3.2 场景覆盖矩阵（manifest 已固化，见 README）

- **调节 S01–S19**：四档组合 ×2 方向、免考逐档（yx501 阶跃）、目标值/增量两种解码、缺数据/废值/L>H 异常剔除、双指令分通道、亚秒 :29舍/:30进。
- **投运 U01–U07**：全投、非电网退出扣罚、电网免责、未并网不计、<99% 罚、阶跃保持读法、副母带电。

### 3.3 回归网

判定实现（含 stub→真实切换）每次改动 CI 跑全 26 场景。任一场景结论偏离 manifest 即 CI 红。**新增算法分支时**：先加一个场景到生成器（定义数据特征 + 期望结论）→ 再写实现 → CI 绿。测试先于实现（TDD）。

## 4. L3 · source 层集成

测后端只读层把外部源读对。**注入方式**：用生成器产出的 SQL 建一个内存 MySQL（Testcontainers）或独立测试库，灌入合成数据，断言读取结果。

| 用例 | 断言 |
|---|---|
| varchar 取整 | 原始 `09:57:57.100`（jitter）读回后取整归 09:58 |
| 双写去重 | 同时刻 busbar 0+1 两条不丢、不重 |
| 排序 | 按 `(save_time, busbar_num)` 有序 |
| 母线过滤 | `busbar_num IN (0,1,2)` 正确分组 |
| 坏行跳过 | 故意插一条畸形 `save_time` → 跳过+记日志，不炸整批 |
| 写保护 | source 层无任何 INSERT/UPDATE/DELETE 路径（代码审查 + 运行时断言） |

## 5. L4 · 部署 E2E

`docker compose up` 起全 4 容器后的黑盒验证，**不依赖算法**。

| 用例 | 断言 |
|---|---|
| 容器健康 | mysql/redis/backend/nginx 全 healthy |
| 登录 | admin 登录拿 JWT |
| 前端取数 | `/vqms/curve` 返回 `qheatavchisdb` 的合成曲线（非 mock、非空） |
| API 前缀剥离 | dev `/dev-api`、prod `/prod-api` 均正确转发 |
| 账号隔离 | `vqms_app` 无 DDL/跨库权限（尝试 CREATE TABLE 应拒） |
| 真实库零污染 | E2E 后 `_qheatavchisdb`（真实数据）行数不变 |

## 6. L5 · 真实数据验证

接入 `_qheatavchisdb`（真实 AVC 数据）后，验证"读层对真实数据的鲁棒性"。**已知局限**：真实数据是退化稳态（`high=low=avg`、`plan_SV` 多为废值、`yc_history` 空、无 warn_type=5），**跑不出越限/判定分支**——所以 L5 验证的是"读得回、不炸、去重对"，不是"判定对"。

| 用例 | 断言 | 局限 |
|---|---|---|
| 真实曲线读取 | `his_curve_sv` 2279 行全读回、双写对齐 | 稳态无波动，判定必全合格（不验证越限） |
| busbar 0/1/2 | 三条母线独立分组 | — |
| warn_type 分布 | 真实只有 2/7/8，**无 5**（确认指令须合成） | 无法验指令解码 |
| yc_history | 真实 0 行 | 投运率/电压/门控全靠合成 |

**结论**：真实数据验证"读层鲁棒性"，合成数据（L2）验证"判定正确性"。两者互补，缺一不可。

## 7. 时间戳 jitter 的测试价值

合成数据时间戳仿真实 dump（`09:57:57.100`，秒 57/58 偏离整点）——这让 L0 取整单测、L3 source 取整集成、L2 场景的 t₀ 锚定**都真正检验到就近取整逻辑**。若用干净整分钟，取整是空操作，测不出 bug。jitter 是测试设计的地基，不可省。

## 8. CI 集成（建议）

```
push → L0(单元) + L2(数据驱动,stub)  ← 快、纯 Python、必跑
PR   → + L3(Testcontainers) + L4(部署 smoke)
发布 → + L5(真实数据,手动或 nightly)
```

慢轨（真实判定实现）的 L2 由"切换实现"的 PR 单独触发全量回归。

## 10. 安全与隔离

- 真实库 `_qheatavchisdb` 在所有自动化测试中**只读**；写测试一律走合成库 `qheatavchisdb`。
- 测试密码走环境变量（`MYSQL57_ROOT_PW` / `VQMS_REALDB_PASSWORD`），不写死、不入库。
- L4 E2E 断言"真实库零污染"作为收尾检查，防止测试误写真实库。
