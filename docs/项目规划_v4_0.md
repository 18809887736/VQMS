## 1. 项目概述与定位

### 1.1 VQMS 是什么

VQMS（Voltage Quality Management System）= 基于 **若依/RuoYi-Vue**（前后端分离版，Spring Security + JWT + Redis）的 AVC 母线电压质量监测与考核系统。主要面向**火电厂**场景；其他电源类型暂不在范围，架构不针对其特化。部署形态：**4 个 Docker Compose 容器**（mysql / redis / backend / nginx）。

> ⚠️ **不是** v2 自研单体（PostgreSQL），**也不是** `y_project/RuoYi`（Shiro + Thymeleaf 单体）。是若依**前后端分离版**。

### 1.2 三大考核维度（附件6）

VQMS 考核功能以《东北区域电力并网运行管理实施细则》《东北区域电力辅助服务管理实施细则》**附件6「AVC 装置技术指标要求及考核规定」**为政策依据（东北能源监管局 2024-09-04 印发，p47–48；原文存 `docs/政策口径/AVC 装置技术指标要求及考核规定.md`）：

| 维度 | 公式 | 合格标准 | 单价 |
|---|---|---|---|
| **① AVC 装置投运率** | 投运时间 / 并网运行时间 × 100%（扣电网原因退出时间） | ≥99% | 每缺 1 个百分点 = 额定容量 × 0.02 分/万千瓦 |
| **② AVC 调节合格率** | 执行合格点数 / 发令次数 × 100% | ≥100% | 同上 |
| **③ 免考** | 已纳入 AVC 闭环的全部无功设备按最大发/吸能力参与仍不达标 → 该时段免于考核 | — | — |

### 1.3 v4.0 的来源（版本演进）

演进链：v1（微服务）→ v2（自研单体/PG）→ v3（RuoYi 底座，主库未定）→ v3.1（RuoYi + **MySQL 定案**，补全 DDL/rollup）→ v3.2（辨析国标区间 vs AVC 控制目标）→ v3.3（统计单元/桶，**已撤销**）→ v3.4（撤销桶、回归 v3.2）→ **v4.0（自洽权威 + 算法搁置 + 前端并入）**。

- **底座（技术栈/架构/API/部署/rollup SQL/账号分离）**：沿用 v3.1，本文 §2/§5/§10/§11/§14 摘其要点。
- **管理表 DDL（`busbar`/`busbar_group`/`yc_point_map`/`busbar_threshold`）+ 时间对齐 + 三步闸门**：沿用 v3.4 §5。

- **前端**：并入原 `docs/前端/前端规划与实施路径.md`（三阶段），本文 §9。

- **MySQL 8.4** — 唯一持久化主库。存 RuoYi `sys_*` 管理表 + VQMS 管理表（`busbar` 等）+ 派生统计。**绝不存原始业务数据**。选 MySQL 因 RuoYi 是 MySQL 原生（建表脚本/分页/社区全部按 MySQL），零方言迁移。
- **Redis** — RuoYi 必需（登录 token、验证码、限流、字典/配置缓存）。
- **External source** — 只读业务数据（`his_curve_sv` 原始曲线、`yc_history` 遥测/门控、`warn_info` 指令）。当前 MySQL 5.7 @ `10.0.0.9 / qheatavchisdb`，按可替换设计。经 RuoYi 多数据源（`@DataSource(SLAVE)`）作只读从库接入。
- **Auth** — RuoYi Spring Security + JWT，原样复用。
- **Backend** = RuoYi 6 原生模块 + **新增 `ruoyi-vqms`**（`source/` + `statistics/` + `ingestion/`）。VQMS Controller 位于 `com.ruoyi.web.controller.vqms`。统计模块被查询 Controller 和 Quartz 作业**进程内直调**（无 Feign、无网关）。

## 3. RuoYi 复用 vs VQMS 自建

RuoYi 解决*通用后台管理系统*，**不解决电压质量**。边界要清晰：

- **原样复用**：登录/JWT、用户/角色/菜单/部门/字典/配置、操作/登录日志、Quartz（含 UI）、POI 导出（`@Excel`）、代码生成、Druid 监控、Swagger、多数据源路由、前端外壳（登录/布局/菜单/个人中心）。RuoYi `sys_*` 表与 `sql/ry_*.sql` 初始化脚本直接用——**不重建管理表**。
- **自建**（VQMS 核心价值）：
  - `source/` — 外部只读层 + 方言切换（§5）。
  - `statistics/` — 判定与合格率算法（**§8 搁置，接口 + stub 占位**）。
  - `ingestion/` — Quartz 预计算作业（**§12 搁置，编排待算法定**）。
  - 前端 `src/views/vqms/` 仪表盘（§9，7 个页面骨架已落地）。
- **升级友好**：所有改动限制在 `ruoyi-vqms` 内，**不修改 RuoYi 原生 6 模块**，跟踪上游 RuoYi 发布时合并成本最小。

## 4. 存储切分铁律

原始电压曲线**绝不复制进 MySQL 主库**。外部源是原始数据唯一真相源；MySQL 只存可重算的派生统计 + 管理数据。`source/` 层（在 `ruoyi-vqms` 内）是通往外部库的**唯一读路径**，且设计为只读（防误写）。拿不准数据在哪时：**raw = 外部源；管理 + 统计 = MySQL**。

---

## 5. 外部数据源只读层（可换方言）

外部源类型预计会变（当前 MySQL 5.7），`source/` 层须保持方言无关——

- 经 `HisCurveSvReader` **接口**访问，返回 JDBC 无关的领域对象；每种方言一个实现（当前 `Mysql57CurveReader`），按 `source.type=mysql57|mysql8|sqlite|postgres` 选 Bean。
- `save_time` 是 `varchar`，日期解析语法因库而异（`STR_TO_DATE`/`strftime`/`to_timestamp`），解析封在实现内或 `SELECT` 原始字符串在 Java 侧解析。
- 配置走 `.env` + `sys_config`（`source.type` + `source.driver/url` + 账号）；切换只改配置 + 换 Bean。
- 只用通用 SQL（`SELECT ... WHERE save_time BETWEEN ? AND ? AND busbar_num = ?`），无 DB 专有写法。
- **承载方式**：复用 RuoYi 多数据源（`@DataSource(SLAVE)` + `AbstractRoutingDataSource`），外部源配为只读 `slave`，与主库 `master` 隔离。

> 管理库 MySQL 是**确定的**；外部源 DB 是**可替换的**。两者不同存储、不同目标，勿混。

#### 6.2.4 `busbar_threshold`（阈值，带生效区间）

> ⚠️ 判定口径已改为草稿 §2 指令级包络（§8）。本表的 `tolerance_v` 在旧 v3.4 `|average_SV−plan_SV|≤tolerance_v` 口径下是判定核心；**在新口径下其角色待重新定位**（草稿判定用 `warn_info` 目标 + 包络区间，不再读 `plan_SV`/`tolerance_v`）。表结构可先建，数值与角色待算法定稿时再定。

```sql
CREATE TABLE `busbar_threshold` (
  `threshold_id`    bigint(20)    NOT NULL AUTO_INCREMENT COMMENT '主键',
  `busbar_num`      bigint(20)    NOT NULL                COMMENT '母线编号（逻辑 FK → busbar.busbar_num）',
  `criterion_type`  varchar(8)    NOT NULL DEFAULT 'AVC'  COMMENT '口径：AVC=控制达标率 / GB=国标±10%',
  `tolerance_v`     decimal(10,3) DEFAULT NULL            COMMENT 'AVC 容差(kV)：220kV=1.000, 500kV=1.500；GB 口径为空。⚠️新口径下角色待定',
  `plan_sv_invalid_policy` varchar(20) NOT NULL DEFAULT 'SKIP' COMMENT 'plan_SV 废值策略：SKIP/COUNT_UNQUALIFIED/FALLBACK',
  `effective_from`  date          NOT NULL                COMMENT '生效起始日（含）',
  `effective_to`    date          DEFAULT NULL            COMMENT '生效结束日（含），NULL=至今有效',
  `create_by`       varchar(64)   DEFAULT '',
  `create_time`     datetime      DEFAULT CURRENT_TIMESTAMP,
  `update_by`       varchar(64)   DEFAULT '',
  `update_time`     datetime      DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  `remark`          varchar(255)  DEFAULT NULL,
  PRIMARY KEY (`threshold_id`),
  KEY `idx_busbar_effective` (`busbar_num`, `effective_from`, `effective_to`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci COMMENT='VQMS 母线电压合格阈值（带生效区间）';

INSERT INTO `busbar_threshold` (`busbar_num`, `criterion_type`, `tolerance_v`, `effective_from`) VALUES
  (0, 'AVC', 1.000, '2026-01-01'),
  (1, 'AVC', 1.000, '2026-01-01');
```

- **生效区间 + 不重算**：按「被统计日期」查 `effective_from ≤ 当天 ≤ effective_to` 的阈值行；阈值变更只影响之后，历史不回溯重算。
- **生效区间不重叠**：DB 难以约束区间不重叠，"新增阈值"须包业务逻辑（先闭合旧记录的 `effective_to`，再插入新行，同一事务）。
- 物理 FK 不建（外部库跨库 FK 无意义；与 RuoYi 风格一致）。

### 6.3 派生统计表（⚠️ 待算法定稿后设计）

草稿 §2 调节合格率是**指令级**（分母=发令次数、两档平行）。v3.4 的 `voltage_quality_daily/monthly/yearly`（分钟级、分母=分钟数、`average_SV`/`plan_SV` 口径）**口径不符，不能复用**作调节合格率落库。指令级表结构（指令明细 + 日/月/年 rollup）**待 §8 算法定稿后设计**——这是搁置轨，确定轨（§6.2 管理表）不受影响。投运率（草稿 §1，时间记账）落库表同样待设计。

## 7. AVC 考核规定（政策依据）

### 7.1 合格区间（电压调整允许偏差）= `tolerance_v` 容差权威值

| 电压等级 | 允许偏差 |
|---|---|
| 500 kV | ±1.5 kV (±1500 V) |
| 220 kV | ±1 kV (±1000 V) |
| 66 kV 及以下 | ±1% 额定电压 |

> ✅ `busbar_threshold.tolerance_v` 已据此统一为 kV：原误值 220kV=300 / 500kV=500（int 伏特）已改为 `decimal(10,3)` kV，值 **1.000 / 1.500**。

### 7.2 调节合格率两档分档（VQMS 细化）

附件6 §二 的"1 分钟内"为合格线；不合格部分（>1 分钟）按响应时长分两档。**两档平行考察、互不隶属、不 fall-through**——见 §8.4。

### 7.3 考核单价

每缺 1 个百分点 = 额定容量 × **0.02 分/万千瓦**，线性（非分档）。投运率、调节合格率缺额通用。

## 8. 判定与算法（⚠️ 草稿为准，搁置预留）

> **本节是 v4.0 的"算法搁置预留"核心。** 判定口径以 `docs/AVC考核核心算法_草稿.md` §2 调节合格率为准（2026-08-13 Leo 拍板），但草稿**仍未定稿**（待真实数据验证 §2.8）。工程上把判定逻辑抽象为接口 + stub 占位，上层框架照样跑通，算法定型后只换实现。

### 8.1 调节合格率目标口径（草稿 §2，对接用）

**判定对象**：一条 AVC 指令（`warn_info` 表 `warn_type=5` 记录，含目标值/增量值），**不是逐分钟**。

**目标电压 `V_target`（kV）**——从指令解码，**不从 `his_curve_sv.plan_SV` 取**：
- 目标值形态：文本数值 `÷100` → kV（如 `22315` → 223.15 kV）；
- 增量值形态：解码 4 位编码 → 幅值 × 100V × 方向，**+ t₀ 时刻当前实时母线电压** → 绝对目标（如 `2202`=+200V；234.25 + 0.2 → 234.45 kV）。

**区间聚合（包络并集）**：N 分钟窗口内每分钟一组 `(high_SV_k, low_SV_k)`，聚合为综合区间 `[L_N, H_N] = [min(low_SV_1..N), max(high_SV_1..N)]`——窗口内电压摆动**曾覆盖的最宽范围**。

**判定**：`V_target ∈ [L_N, H_N]` = 该窗合格。

**逐分钟字段在判定中的角色**：

| 字段 | 角色 | 说明 |
|---|---|---|
| `high_SV` / `low_SV` | **判定用**（聚合进包络） | 窗口观测极值，取 max/min 构成 `[L,H]` |
| `average_SV` | 不参与判定 | 旧模型用，草稿已弃 |
| `plan_SV` | 不参与判定 | 目标来自 `warn_info`；样例值 `10245` 是废值，跳过+记日志，不解码 |

### 8.2 算法搁置预留的工程做法（核心决策）

判定算法是最不稳定的一块。把它抽象成**接口**，先放 **stub 实现**，上层框架照样能跑通；算法定型后**只换实现、不动调用方**：

```java
// statistics 包内的判定接口（输入/输出稳定，与算法细节解耦）
public interface RegulationJudge {
    /** 对一条 AVC 指令做两档平行判定。
     * @param cmd       指令（warn_info 解码后的 V_target、t₀、主母线）
     * @param curveByMinute  窗口内逐分钟 (high_SV, low_SV)，已时间对齐
     * @param params    整定参数（T_fast / T_econ 等，来自阈值表/配置）
     * @return 两档独立结论 {fast: VERDICT, econ: VERDICT} */
    RegulationVerdict judge(AvcCommand cmd,
                            List<MinuteCurve> curveByMinute,
                            JudgeParams params);
}

// VERDICT ∈ {QUALIFIED, PENALIZED, EXEMPT}（合格 / 不合格 / 免考剔除）
```

**搁置期用 stub**：`StubRegulationJudge implements RegulationJudge`，返回全 `QUALIFIED` 或随机三态——只保证上层"能编译、能调通、有返回值"，不保证正确。算法定型后替换为真实 `DefaultRegulationJudge`，调用方零改动。

> 接口的**输入/输出契约是稳定的**（一条指令 + 窗口曲线 + 参数 → 两档三态结论），即使草稿 §2.8 的细节（`T_econ` 上限、解码位定义、缺数据策略）调整，也只影响实现内部，不破坏接口。

### 8.3 投运率目标口径（草稿 §1）

`AVC 投运率 = AVC 投运时间 / 并网运行时间 × 100%`，合格 ≥99%。`yc_history` 的 AVC 投退 yx 点（`yc_data` 1=投/0=退，阶跃保持），免责=扣除电网原因退出时间。退出原因来源（`warn_info`/`yc_history` 是否有退出原因点位）**待定**——投运率也属搁置轨，判定同样走接口 + stub。

### 8.4 两档关系（平行独立，不 fall-through）

快速性档与经济性档是**两个并列的独立考核项**。两档**并行**各判一次（各自综合区间是否夹住 `V_target`）、**各档不合格逐档判免考**（免考结论不跨档）、**各出各的合格率、各算各的罚款，相加得总罚款**。一条指令可有两个独立结论（如「快速性不合格 + 经济性合格」合法）。旧的串联 fall-through 模型**已废弃**。

| 档 | 扫描窗口 | 综合区间 | 罚的是 |
|---|---|---|---|
| 快速性档 | 第 1 ~ `T_fast` 分钟 | `[L_fast, H_fast]` | 调得慢（动态性能） |
| 经济性档 | 第 `T_fast+1` ~ `T_econ` 分钟 | `[L_econ, H_econ]` | 持续越限（经济代价） |

整定参数：`T_fast` 默认 5 min、`T_econ` 待定（需定上限），现场可整定。权威定义见草稿 §2.4–2.7。

### 8.5 草稿待定项（§2.8，需真实数据验证）

| 项 | 处理 |
|---|---|
| 窗口内某分钟缺数据 | 暂定跳过（不计 min/max）+ 记日志；整窗全缺→指令判定失效、剔除 |
| `T_econ` 上限 | "≥5min"无上界会使长越限永远合格；**需定上限**（如 30 min） |
| 目标值/增量解码失败 | 跳过 + 记日志，不计入发令次数 |
| 多条指令时间重叠 | 按 `obj_num`/主母线分通道，各判各的 |
| 缺当前实时电压（增量形态） | 取 t₀ 最近一条；缺失则跳过 |
| 综合区间 `L > H`（数据异常） | 该窗无效，记日志 |
| 增量第 2 位"循环码"含义 | 待真实数据验证 |

## 13. 单位规约

VQMS 全项目统一采用以下规范单位，字段、计算、文档、UI 展示均以此为准：

| 量 | 规范单位 | 存储 | 说明 |
|---|---|---|---|
| 电压（`average_SV`/`high_SV`/`low_SV`/`plan_SV`/`nominal_kv`/`tolerance_v`） | **kV** | decimal | 源数据即整数 kV（220kV 母线 `average_SV`≈234）；`tolerance_v` 用 `decimal(10,3)`（1.000/1.500） |
| 无功功率 | **kvar** | decimal | 引用 AVC 原文时照录"万千乏"（1 万千乏 = 10000 kvar） |
| 有功 / 容量 | **kW** | decimal | 引用原文时照录"万千瓦" |
| 合格率 / 投运率 | **%** | decimal | 聚合按发令次数（调节合格率）或分钟数（投运率）加权 |
| 时间（聚合） | **分钟数** | int | 投运率记投运/退出分钟计数；调节合格率记指令计数 |

**单位一致性**：源 SV 字段读入后**不做单位换算**（原值即 kV）。参与比较的电压量必须同单位（kV）。`yc_history` 模拟量按 `yc_point_map.unit` 标注，纳入统计前归一到规范单位。

**时间原则：就近取整到分钟（秒 ≥ 30 进位）**——`his_curve_sv`/`yc_history` 的毫秒精度原始时间戳在任何逐分钟聚合前就近取整到分钟（秒≥30 进位，<30 舍去），是所有判定与汇总的对齐基础；**不要 floor/截断，也不要按原始秒分组**。
