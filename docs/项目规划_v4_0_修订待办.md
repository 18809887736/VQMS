## A. 核心必改（9 项）

### A1. §8.2 stub 改确定性
- **位置**：§8.2（约第 319 行），`StubRegulationJudge` 描述。
- **现状**：原文「返回全 `QUALIFIED` 或**随机三态**」。
- **改为**：确定性 stub——按输入 hash 出确定结论（或固定全 QUALIFIED），并在返回里带 `stub=true` 标记。
- **原因**：随机返回让测试/集成不可复现，且会污染任何落库或缓存。注：后端 `ruoyi-vqms` 尚未落地，stub 还没真正运行，故当前是「潜在风险」而非已发生事故；改确定性仍是标准好习惯。

### A2. §8 RegulationJudge 重构为三阶段管线（最核心 · 论据已修正）
- **位置**：§8.2 接口契约（约第 305–321 行）。
- **现状**：接口 `judge(AvcCommand cmd, List<MinuteCurve> curveByMinute, JudgeParams params)` 输出 `VERDICT ∈ {QUALIFIED, PENALIZED, EXEMPT}`；§8.2（第 321 行）宣称「接口契约稳定……不破坏接口」。但**免考与门控数据在接口输入里没有通道**——算法定型要塞这两类数据时签名必然改，与「不动调用方」自相矛盾。
- **改为（三阶段管线）**：
  1. **门控前置过滤**（调用方做）：读 `yc_history` 的 AVC投退/远方就地 yx 点，排除 AVC 退出/就地模式时段的指令。**不进 judge**。
  2. **RegulationJudge 包络判定**：**从返回值移除 `EXEMPT`**，只出 `{QUALIFIED, PENALIZED}`。输入自洽，真正实现「只换实现、不动调用方」。
  3. **免考后置应用**（非判定）：**读对端 `yx501`**（全厂一个，0/1），PENALIZED + yx501=1 → 标记免考、剔除该档分母。免考判定（Q vs 极限）是对端义务，不进 VQMS judge。
- **原因（⚠️ 2026-08-14 论据修正）**：门控=前置作用域、免考=后置覆盖（草稿 §2.6 包络失败后才判），架构上不同。**原论据「免考判不了、EXEMPT 不可达」已证伪**——免考数据对端 GENERATOR 库齐全（`qYcNum`=yc217/317 逐机 Q + `GENERATOR_P_QLimit` 双向极限曲线），`docs/数据源头（草稿）.md` §4 缺口③ 已定「对端 JS 算 `yx501`、VQMS 读结论值」架构。**Leo 2026-08-14 拍板：免考判定归对端、VQMS 不背判定义务**——故 `EXEMPT` 不该是 judge（VQMS 判定接口）的输出，它是后置读 yx501 的**应用结果**，不是判定产物。
- **附带（finding A，解码归属）**：`AvcCommand` 应携带 `warn_info` 原始字段 + t₀ 实时母线电压，**解码留在 judge 实现内部**，不要让调用方预算 `V_target`（否则草稿 §2.8「循环码」位定义等解码变更会迫使调用方改动，违反「不动调用方」）。

### A3. §8.5 解码失败处理（加独立计数 + 合规确认）
- **位置**：§8.5 表格（约第 344 行），「目标值/增量解码失败 | 跳过 + 记日志，不计入发令次数」。该行在 §8.5 已标「暂定」。
- **改为**：跳过判定 + 记日志 + **单独计数 `undecodable_count` 并上报**；标注「暂定项，需与政策口径/电厂考核惯例确认」。
- **原因**：调节合格率分母=发令次数，解码失败就剔除分母=系统性抬高合格率，有合规风险。记日志留了运维痕迹但修不了分母抬高；审计看的是统计数字本身。
- **详细**：数据举例、三种处理对比、归因上报见 [数据不可用处理策略](数据不可用处理策略.md) §4（与 #3 缺数据统一）。
- **⚠️ 状态更新（2026-08-15）**：本项已按 **A9 搁置预留**——`undecodable_count` 计数契约保留（只记不判），处置策略随搁置轨解封时定。

### A6. 判定整定参数 CRUD 方案（自建表 `vqms_judge_param`）
- **背景**：`t_fast` / `t_econ` / 分档阈值是现场可整定的判定参数，需「初始值 + 运行时 CRUD 读写 + 改后即时生效」（对应会议清单 #1/#2）。Leo 2026-08-14 拍板走自建表。
- **存储**：新建 VQMS 自管表 `vqms_judge_param`，与 `busbar_threshold` 并列。**不用** RuoYi `sys_config`（要值域校验 / 结构化可读 / 归属清晰 / 操作日志，键值对给不了）。
- **DDL（utf8mb4）**：
  `param_id BIGINT PK AUTO_INCREMENT`、`param_key VARCHAR(64) NOT NULL UNIQUE`、`param_value INT NOT NULL`（分钟数）、`name VARCHAR(64) NOT NULL`、`description VARCHAR(255)`、`value_min INT`、`value_max INT`、`status CHAR(1) DEFAULT '0'`、`create_by/create_time`、`update_by/update_time`、`remark`。
- **初始值与值域**（Leo 2026-08-14 定）：
  - `t_fast`：范围 **[1,5)**（整数 1–4），自由整定；默认值待定（建议 **4**）。快速性档窗口 = [1, `t_fast`]。
  - `t_econ` = **5**（**写死、固定，不再可整定**）。经济性档窗口 = [`t_fast`+1, 5]。
  - `tier_threshold_fast` = **1**、`tier_threshold_econ` = **5**（附件6 政策值，锁）。
  - **指令间隔 = 5 分钟**（Leo 确认：现场 AVC 实际就是 5 分钟一条）→ 判定窗口 = 间隔 = 5 分钟：**指令重叠不发生（#4 解决）、`T_econ` 无上限隐患（#1 解决）**。
- **CRUD**：RuoYi 代码生成 `/vqms/judgeParam` + Vue 页面，挂菜单「VQMS 管理 → 判定参数」，perms `vqms:judgeParam:list/add/edit/remove`，操作日志自动。
- **读写生效**：判定时读表 + **Redis 缓存** `vqms:judgeParam:{key}`；CRUD 改完 `CacheEvict` 刷新、下次判定读新值；启动灌缓存。
- **值域校验**（Service 层）：`t_fast` ∈ [1,5) 整数、且 < `t_econ`(=5)；`t_econ` 锁定 5；分档阈值 1/5 锁定。
- **归属**：确定轨实施（不依赖算法定稿），归 `ruoyi-vqms`。

### A8. 电压等级维度定位（不建独立统计维度；字典 + 前端筛选）
- **背景**：2026-08-15 Leo 提问「是否该加 500kV / 220kV / 66kV及以下 电压等级维度」，关联会议清单 #13（500kV 母线补录后 UI 如何按等级呈现）。
- **决策（Leo 2026-08-15 拍板）**：
  1. **不建独立统计维度**。三层理由：① 附件6 考核口径是**厂级**（投运率/调节合格率 + 额定容量计罚），不按电压等级各考一摊；② 统计本就按 `busbar_num` 落，`v_grade` 经 join `busbar` 恒可得，无需冗余；③ 搁置轨统计 DDL 未定，现在加 `v_grade` 列 = 提前写没定的 DDL（搁置轨红线）。
  2. **元数据层已有**：`busbar.v_grade` / `busbar_group.v_grade`（0=500kV、1=220kV、可扩展，§6.2）——等级是**母线属性**而非独立统计轴。
  3. **落地两件事（确定轨，已实施）**：
     - **RuoYi 字典 `vqms_v_grade`**（0=500kV、1=220kV、**2=66kV及以下·预留**），编码值与 `busbar.v_grade` 严格对齐、勿改——已加 `sql/vqms.sql` 第六节（delete+insert 幂等）。
     - **前端母线维度 5 页**（curve / daily / monthly / yearly / threshold）加「电压等级」筛选，选项来自字典；curve/daily/monthly/yearly 的母线下拉按等级**级联过滤**（阶段 2 用本地种子占位，后端 `/vqms/busbar` 就绪后改接口拉取）；daily/monthly/yearly 表格加电压等级列（`dict-tag` 渲染 `row.vGrade`，**后端 list 接口行须带 `vGrade` 字段**，join `busbar`）。
  4. **不适用页面**：avc-runtime / avc-regulation 两页是**并网主体（厂级）口径**，无母线维度，**不加**该筛选——与「考核对象是电厂」自洽；日后若调节合格率细化到母线再补。
  5. **66kV及以下**：本站暂无数据（`his_curve_sv` 只有 220kV 母线 0/1，500kV 待 #13 补录）；其容差口径为 **±1% 额定电压**（异于 500kV/220kV 的固定 kV 档），真出现时录入 `busbar` 行 + 字典启用即可，模型/表结构不改。

### A9. 数据不可用处理策略（#3 缺数据 / #5 解码失败）搁置预留——随搁置轨解封时定稿
- **决策（Leo 2026-08-15 拍板）**：为不阻塞进度，#3 缺数据策略与 #5 解码失败处置**不再要求会上先行定稿**，按搁置预留处理，与判定实现、统计 DDL、Quartz 编排**同批解封时一并定**。对应 [遗留问题.md](遗留问题.md) 第三条。
- **为什么能搁（结构性理由）**：缺分钟处理与解码失败处置都发生在 **judge 实现内部**（A2 已定「解码留在 judge 实现内」），判定实现本就在搁置轨——策略天然同生命周期。确定轨 D1~D6（source 层 / 管理表 / 时间对齐 / 闸门 / 脚手架 / 前端）不消费这两个决策，搁置**不阻塞任何确定轨工作**。
- **搁置方案（三条）**：
  1. **选套推迟**：甲/乙/丙/丁不硬编码进任何代码，随解封与统计 DDL 同批定（若选丁需统计表加透明标记列——DDL 同批解封，无冲突）。
  2. **保留策略无关的确定轨契约——原始计数只记不判**：发令次数、`undecodable_count`、窗口缺分钟数照实记录、**不应用任何处置**。理由：四套候选消费的是**同一套计数**，先记后定不吃亏；反之现在不记，将来选了套也无法回溯重算。
  3. **参数钩子现成**：乙档 50% 阈值将来 = `vqms_judge_param` 加一行参数即可，无需现在预留新结构。
- **两个边界（勿混淆）**：
  - **读取层「坏行跳过 + 记日志」闸门照旧**——那是读取鲁棒性（不让整批失败），**不是** #3 策略；属确定轨，照做不受搁置影响。
  - **真实统计上线前仍须定稿**——合规风险（剔除分母抬高合格率）出在「应用策略」那一刻，搁置期间不产生；但**解封时 #3/#5 重新成为前置条件**（与草稿 §2.8 待定稿项一并收口）。
- **连带状态更新**：A3、A7 由「待定」改「随 A9 搁置」（上文已注记）；会议清单 #3/#5 从「会上当场定」降级为「随搁置轨解封」，不再占用表决时间。
