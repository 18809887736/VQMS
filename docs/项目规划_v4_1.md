## 1. 项目概述与定位

### 1.1 VQMS 是什么

VQMS（Voltage Quality Management System）= 基于 **若依/RuoYi-Vue**（前后端分离版，Spring Security + JWT + Redis）的 AVC 母线电压质量监测与考核系统。主要面向**火电厂**场景；其他电源类型暂不在范围，架构不针对其特化。部署形态：**4 个 Docker Compose 容器**（mysql / redis / backend / nginx）。

> ⚠️ **不是** v2 自研单体（PostgreSQL），**也不是** `y_project/RuoYi`（Shiro + Thymeleaf 单体）。是若依**前后端分离版**。

### 1.2 三大考核维度（附件6）

VQMS 考核功能以《东北区域电力并网运行管理实施细则》《东北区域电力辅助服务管理实施细则》**附件6「AVC 装置技术指标要求及考核规定」**为政策依据（东北能源监管局 2024-09-04 印发，p47–48；原文存 `docs/政策口径/AVC 装置技术指标要求及考核规定.md`）：

| 维度 | 公式 | 合格标准 | 单价 |
|---|---|---|---|
| **① AVC 装置投运率** | 投运时间 / 并网运行时间 × 100%（扣电网原因退出时间） | ≥99% | 每缺 1 个百分点 = 额定容量 × 0.02 分/万千瓦 |
| **② AVC 调节合格率** | 执行合格点数 / 发令次数 × 100% | ≥100% | 同上 |
| **③ 免考** | 已纳入 AVC 闭环的全部无功设备按最大发/吸能力参与仍不达标 → 该时段免于考核 | — | — |

> **免考分工边界（Leo 2026-08-14 拍板）**：免考判定（Q vs 极限）是**对端义务**——对端 JS 算好全厂免考标志 `yx501`（0/1），VQMS 只读结论值、不背判定义务。工程上免考是后置应用（§8.2 阶段三），不是判定产物。

### 1.3 v4.1 的来源（版本演进）

演进链：v1（微服务）→ v2（自研单体/PG）→ v3（RuoYi 底座，主库未定）→ v3.1（RuoYi + **MySQL 定案**，补全 DDL/rollup）→ v3.2（辨析国标区间 vs AVC 控制目标）→ v3.3（统计单元/桶，**已撤销**）→ v3.4（撤销桶、回归 v3.2）→ v4.0（自洽权威 + 算法搁置 + 前端并入）→ **v4.1（合并修订待办：三阶段管线 + 判定参数表 + 数据不可用策略搁置）**。

- **MySQL 8.4** — 唯一持久化主库。存 RuoYi `sys_*` 管理表 + VQMS 管理表（`busbar` 等）+ 派生统计。**绝不存原始业务数据**。选 MySQL 因 RuoYi 是 MySQL 原生（建表脚本/分页/社区全部按 MySQL），零方言迁移。
- **Redis** — RuoYi 必需（登录 token、验证码、限流、字典/配置缓存）；另承载判定参数缓存 `vqms:judgeParam:{key}`（§6.2.5）。
- **External source** — 只读业务数据（`his_curve_sv` 原始曲线、`yc_history` 遥测/门控、`warn_info` 指令）。当前 MySQL 5.7 @ `10.0.0.9 / qheatavchisdb`，按可替换设计。经 RuoYi 多数据源（`@DataSource(SLAVE)`）作只读从库接入，**连接账号为 `GRANT SELECT`-only**（§11）。
- **Auth** — RuoYi Spring Security + JWT，原样复用。
- **Backend** = RuoYi 6 原生模块 + **新增 `ruoyi-vqms`**（`source/` + `statistics/` + `ingestion/`）。VQMS Controller 位于 `com.ruoyi.web.controller.vqms`。统计模块被查询 Controller 和 Quartz 作业**进程内直调**（无 Feign、无网关）。

## 3. RuoYi 复用 vs VQMS 自建

RuoYi 解决*通用后台管理系统*，**不解决电压质量**。边界要清晰：

- **原样复用**：登录/JWT、用户/角色/菜单/部门/字典/配置、操作/登录日志、Quartz（含 UI）、POI 导出（`@Excel`）、代码生成、Druid 监控、Swagger、多数据源路由、前端外壳（登录/布局/菜单/个人中心）。RuoYi `sys_*` 表与 `sql/ry_*.sql` 初始化脚本直接用——**不重建管理表**。
- **自建**（VQMS 核心价值）：
  - `source/` — 外部只读层 + 方言切换（§5）。
  - `statistics/` — 判定与合格率算法（**§8 搁置，接口 + stub 占位**）。
  - `ingestion/` — Quartz 预计算作业（**§12 搁置，编排待算法定**）。
  - 前端 `src/views/vqms/` 仪表盘（§9，7 个页面骨架已落地）。
- **升级友好**：所有改动限制在 `ruoyi-vqms` 内，**不修改 RuoYi 原生 6 模块**，跟踪上游 RuoYi 发布时合并成本最小。

## 4. 存储切分铁律

原始电压曲线**绝不复制进 MySQL 主库**。外部源是原始数据唯一真相源；MySQL 只存可重算的派生统计 + 管理数据。`source/` 层（在 `ruoyi-vqms` 内）是通往外部库的**唯一读路径**，且设计为只读（防误写）。拿不准数据在哪时：**raw = 外部源；管理 + 统计 = MySQL**。**唯一有界例外（Leo 2026-08-17 拍板）**：`vqms_command_ledger` 指令流水账（§6.2.6）——外部源 `warn_info` 指令的**原始字段只增摘录表**，为搁置期计数契约（§8.6）提供落库底账；除这一张表外，原始数据（曲线等）仍绝不入主库。

## 5. 外部数据源只读层（可换方言）

外部源类型预计会变（当前 MySQL 5.7），`source/` 层须保持方言无关——

- 经 `HisCurveSvReader` **接口**访问，返回 JDBC 无关的领域对象；每种方言一个实现（当前 `Mysql57CurveReader`），按 `source.type=mysql57|mysql8|sqlite|postgres` 选 Bean。
- `save_time` 是 `varchar`，日期解析语法因库而异（`STR_TO_DATE`/`strftime`/`to_timestamp`），解析封在实现内或 `SELECT` 原始字符串在 Java 侧解析。
- 配置走 `.env` + `sys_config`（`source.type` + `source.driver/url` + 账号）；切换只改配置 + 换 Bean。
- 只用通用 SQL（`SELECT ... WHERE save_time BETWEEN ? AND ? AND busbar_num = ?`——注意三表时间列名不同，见下速查），无 DB 专有写法。
- **三表真实列名速查（防实现踩坑）**：

| 表 | 时间列 | 其余关键列 |
|---|---|---|
| `his_curve_sv` | `save_time`（varchar，带毫秒） | `busbar_num` / `high_SV` / `low_SV`（判定用）/ `average_SV`、`plan_SV`（废值） |
| `yc_history` | **`yc_time`**（不是 save_time） | `yc_num` / `yc_data` |
| `warn_info` | `warn_time`（毫秒另列） | `warn_type` / `obj_num` / **指令目标值/增量值编码在 `warn_info` 文本列内**（无结构化指令值列，解码口径见 §8.1） |

- **时间取整责任边界（Leo 2026-08-17 确认）**：reader 对外返回**原始时间戳**（不丢精度）；D4 ③ 闸门的就近取整（§13）仅在 reader 内部用于边界裁剪；judge 侧窗口对齐由**调用方**经 D3 工具完成——就近取整幂等（已整到分钟的值不再变化），双重取整无害。
- **承载方式**：复用 RuoYi 多数据源（`@DataSource(SLAVE)` + `AbstractRoutingDataSource`），外部源配为只读 `slave`，与主库 `master` 隔离。
- **只读落到 DB 层**：路由约定（`@DataSource(SLAVE)`）不防误写，外部源连接账号必须是 `GRANT SELECT`-only 账号（§11），把只读从代码约定升级为 DB 层强制。

> 管理库 MySQL 是**确定的**；外部源 DB 是**可替换的**。两者不同存储、不同目标，勿混。

## 6. 数据库设计（管理表 DDL）

### 6.1 管理表（直接用 RuoYi `sys_*`）

RuoYi `sql/` 目录提供 MySQL 建表脚本（`ry_*.sql`、`quartz.sql`）：`sys_user/role/menu/dept/dict_type/dict_data/config/oper_log/logininfor/job` 等。**VQMS 不重建这些表，直接复用**。

### 6.2 VQMS 业务管理表（v3.4 §5，结构先行、数值后填）

> 这六张表（五张管理表 + 一张指令流水账 §6.2.6）落主库 MySQL。**结构现在就能定，初始数值待现场确认后录入**。判定口径已改为草稿 §2 指令级（§8），但管理表字段（母线元数据、阈值数值、点映射、整定参数）与判定实现解耦——管理表不依赖算法定稿，属"确定轨"。

**逻辑 FK 与写路径校验（无物理外键，应用层兜底）**：六表之间不建物理外键（跨库 + 与 RuoYi 风格一致；`vqms_command_ledger` 无跨表引用、不参与本校验），一致性靠应用层。关键写路径必须加**存在性校验**：维护 `busbar` 时校验 `group_num` 在 `busbar_group` 存在；维护 `busbar_group` 时校验 `main_indicator_yc_num`（若非空）在 `yc_point_map` 存在；维护 `busbar_threshold` 时校验 `busbar_num` 存在；删除 `busbar_group` 时校验无 `busbar` 引用。无 DB 层约束时，错漏不会报错、只会在统计结果里悄悄出错。

> 勘误（2026-08-17）：本条原写作「维护 `yc_point_map` 时校验关联 `busbar_num` 存在」——`yc_point_map` 并无 `busbar_num` 列（修订待办 A5 落地时字段名与方向照搬有误），实际逻辑引用是 `busbar_group.main_indicator_yc_num → yc_point_map.yc_num`，已按此纠正。

#### 6.2.1 `busbar`（主母线元数据）

```sql
CREATE TABLE `busbar` (
  `busbar_num`    bigint(20)    NOT NULL                COMMENT '主母线编号，对齐 his_curve_sv.busbar_num',
  `busbar_name`   varchar(64)   NOT NULL                COMMENT '母线名称，如 220kV 正母线',
  `v_grade`       tinyint       NOT NULL                COMMENT '电压等级编码：0=500kV, 1=220kV, 2=66kV及以下(预留)，与字典 vqms_v_grade 严格对齐勿改',
  `group_num`     bigint(20)    DEFAULT NULL            COMMENT '所属母线组（逻辑FK → busbar_group.group_num）',
  `nominal_kv`    decimal(10,3) NOT NULL                COMMENT '标称电压 kV（220.000 / 500.000）',
  `status`        char(1)       NOT NULL DEFAULT '0'    COMMENT '状态：0=正常, 1=停用',
  `create_by`     varchar(64)   DEFAULT '',
  `create_time`   datetime      DEFAULT CURRENT_TIMESTAMP,
  `update_by`     varchar(64)   DEFAULT '',
  `update_time`   datetime      DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  `remark`        varchar(255)  DEFAULT NULL,
  PRIMARY KEY (`busbar_num`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci COMMENT='VQMS 主母线元数据';

-- 初始数据（220kV 东/西母线——对齐外部 BUSBAR 注册表样本（docs/外部DB/外部数据源.md）；
--   warn_info 告警/状态文本对同一对母线称「正母线/副母线」，两套称呼矛盾，最终以现场确认为准；500kV 待现场补录）
INSERT INTO `busbar` (`busbar_num`, `busbar_name`, `v_grade`, `group_num`, `nominal_kv`) VALUES
  (0, '220kV 东母线', 1, 0, 220.000),
```

## 8. 判定与算法（⚠️ 草稿为准，搁置预留）

> **本节是"算法搁置预留"核心。** 判定口径以 `docs/AVC考核核心算法_草稿.md` §2 调节合格率为准（2026-08-13 Leo 拍板），但草稿**仍未定稿**（待真实数据验证 §2.8）。工程上把判定逻辑抽象为接口 + stub 占位，上层框架照样跑通，算法定型后只换实现。

### 8.1 调节合格率目标口径（草稿 §2，对接用）

**判定对象**：一条 AVC 指令（`warn_info` 表 `warn_type=5` 记录，含目标值/增量值），**不是逐分钟**。

**目标电压 `V_target`（kV）**——从指令解码，**不从 `his_curve_sv.plan_SV` 取**：
- 目标值形态：文本数值 `÷100` → kV（如 `22315` → 223.15 kV）；
- 增量值形态：解码 4 位编码 → 幅值 × 100V × 方向，**+ t₀ 时刻当前实时母线电压** → 绝对目标（如 `2202`=+200V；234.25 + 0.2 → 234.45 kV）。

**区间聚合（包络并集）**：N 分钟窗口内每分钟一组 `(high_SV_k, low_SV_k)`，聚合为综合区间 `[L_N, H_N] = [min(low_SV_1..N), max(high_SV_1..N)]`——窗口内电压摆动**曾覆盖的最宽范围**。

**判定**：`V_target ∈ [L_N, H_N]` = 该窗合格。

**逐分钟字段在判定中的角色**：

| 字段 | 角色 | 说明 |
|---|---|---|
| `high_SV` / `low_SV` | **判定用**（聚合进包络） | 窗口观测极值，取 max/min 构成 `[L,H]` |
| `average_SV` | **废值**（不考察） | Leo 2026-08-14 定：当废值处理，source 层不映射；旧模型用，已彻底弃 |
| `plan_SV` | **废值**（不考察） | 目标来自 `warn_info`；样例值 `10245` 是废值，跳过+记日志，不解码 |

### 8.2 算法搁置预留的工程做法（核心决策）：三阶段管线

判定算法是最不稳定的一块。把它抽象成**接口**，先放 **stub 实现**，上层框架照样能跑通；算法定型后**只换实现、不动调用方**。

**整体是三阶段管线**（Leo 2026-08-14 拍板，v4.1 重构）：

1. **门控前置过滤**（调用方做，不进 judge）：读 `yc_history` 的 AVC投退/远方就地 yx 点，排除 AVC 退出/就地模式时段的指令。门控点未补录前 `gate_enabled=0` 空转（§14-7）。
2. **`RegulationJudge` 包络判定**：接口输入自洽（指令 + 窗口曲线 + 参数），**只出 `{QUALIFIED, PENALIZED}` 两态**——**返回值不含 `EXEMPT`**。
3. **免考后置应用**（非判定）：读对端 `yx501`（全厂一个，0/1，对端 JS 算好），`PENALIZED + yx501=1` → 标记免考、剔除该档分母。免考判定（Q vs 极限）是对端义务（§1.2），**不进 VQMS judge**——免考是后置读 yx501 的**应用结果**，不是判定产物。

```java
// statistics 包内的判定接口（输入/输出稳定，与算法细节解耦）
public interface RegulationJudge {
    /** 对一条 AVC 指令做两档平行判定（阶段二：纯包络判定，不含门控/免考）。
     * @param cmd       指令（携带 warn_info 原始字段 + t₀ 时刻实时母线电压；
     *                  V_target 解码留在 judge 实现内部，调用方不预算）
     * @param curveByMinute  窗口内逐分钟 (high_SV, low_SV)，已时间对齐
     * @param params    整定参数（t_fast / t_econ 等，来自 vqms_judge_param）
     * @return 两档独立结论 {fast: VERDICT, econ: VERDICT} */
    RegulationVerdict judge(AvcCommand cmd,
                            List<MinuteCurve> curveByMinute,
                            JudgeParams params);
}

// VERDICT ∈ {QUALIFIED, PENALIZED}（v4.1 起移除 EXEMPT——免考是阶段三的后置应用）
```

**两个设计要点**：

- **解码归属（为什么调用方不预算 `V_target`）**：`AvcCommand` 携带 `warn_info` 原始字段 + t₀ 实时母线电压，**解码留在 judge 实现内部**。否则草稿 §2.8「循环码」位定义等解码变更会迫使调用方改动，违反「不动调用方」。
- **门控/免考为什么不进 judge**：门控 = 前置作用域（决定"判不判"）、免考 = 后置覆盖（草稿 §2.6 包络失败后才读 yx501），架构上分层不同；塞进接口会让签名随算法定型必然改，与「接口契约稳定」自相矛盾。这样接口输入自洽，真正实现「只换实现、不动调用方」。

**搁置期用确定性 stub**：`StubRegulationJudge implements RegulationJudge`，**按输入 hash 出确定结论（或固定全 `QUALIFIED`），返回值带 `stub=true` 标记**——**禁止随机三态**（随机返回让测试/集成不可复现，且会污染任何落库或缓存）。只保证上层"能编译、能调通、有返回值"，不保证正确。算法定型后替换为真实 `DefaultRegulationJudge`，调用方零改动。

> 接口的**输入/输出契约是稳定的**（一条指令 + 窗口曲线 + 参数 → 两档两态结论），即使草稿 §2.8 的细节（解码位定义、缺数据策略）调整，也只影响实现内部，不破坏接口。

### 8.3 投运率目标口径（草稿 §1）

`AVC 投运率 = AVC 投运时间 / 并网运行时间 × 100%`，合格 ≥99%。`yc_history` 的 AVC 投退 yx 点（`yc_data` 1=投/0=退，阶跃保持），免责=扣除电网原因退出时间。退出原因来源（`warn_info`/`yc_history` 是否有退出原因点位）**待定**——投运率也属搁置轨，判定同样走接口 + stub。

### 8.4 两档关系（平行独立，不 fall-through）

快速性档与经济性档是**两个并列的独立考核项**。两档**并行**各判一次（各自综合区间是否夹住 `V_target`）、**各档不合格逐档判免考**（免考结论不跨档）、**各出各的合格率、各算各的罚款，相加得总罚款**。一条指令可有两个独立结论（如「快速性不合格 + 经济性合格」合法）。旧的串联 fall-through 模型**已废弃**。

| 档 | 扫描窗口 | 综合区间 | 罚的是 |
|---|---|---|---|
| 快速性档 | 第 1 ~ `t_fast` 分钟 | `[L_fast, H_fast]` | 调得慢（动态性能） |
| 经济性档 | 第 `t_fast+1` ~ 5 分钟 | `[L_econ, H_econ]` | 持续越限（经济代价） |

**整定参数（Leo 2026-08-14 定，存 `vqms_judge_param`，§6.2.5）**：`t_fast` ∈ **[1,5)**（整数 1–4，自由整定，默认建议 **4**）、`t_econ` = **5 写死**；**指令实际 5 分钟间隔 → 判定窗口 = 5 分钟，两档不重叠、指令重叠不发生、`T_econ` 无上限隐患消除**。权威定义见草稿 §2.4–2.7。

### 8.5 草稿待定项（§2.8，需真实数据验证）

| 项 | 处理 |
|---|---|

| ~~`T_econ` 上限~~ | ✅ **已解决（2026-08-14）**：`t_econ`=5 写死 + 指令 5 分钟间隔 → 窗口 5 分钟，无上限隐患消除（§6.2.5/§8.4） |

### 8.6 数据不可用处理策略（#3 缺数据 / #5 解码失败）——搁置预留

**决策（Leo 2026-08-15 拍板）**：为不阻塞进度，#3 缺数据策略与 #5 解码失败处置**不再要求先行定稿**，按搁置预留处理，与判定实现、统计 DDL、Quartz 编排**同批解封时一并定**（对应 `docs/遗留问题.md` 第三条；候选方案详见 `docs/数据不可用处理策略.md` §3/§4）。

- **为什么能搁（结构性理由）**：缺分钟处理与解码失败处置都发生在 **judge 实现内部**（§8.2 已定「解码留在 judge 实现内」），判定实现本就在搁置轨——策略天然同生命周期。确定轨 D1~D7（source 层 / 管理表 / 时间对齐 / 闸门 / 脚手架 / 前端 / 判定参数）不消费这两个决策，搁置**不阻塞任何确定轨工作**。
- **搁置方案（三条）**：
  1. **选套推迟**：甲/乙/丙/丁不硬编码进任何代码，随解封与统计 DDL 同批定（若选丁需统计表加透明标记列——DDL 同批解封，无冲突）。
  2. **保留策略无关的确定轨契约——原始事实落 `vqms_command_ledger`（§6.2.6，Leo 2026-08-17 拍板）**：发令次数 = 流水行数，**照实落库、只记不判**；`undecodable_count` 与窗口缺分钟数**不预计算**（前者依赖搁置轨解码器、后者依赖窗口计算），**解封后从流水原文 + 外部源曲线重算**。指令原文在库，解码位定义（循环码）定稿后可整体重新解码——「先记后定不吃亏」由此成立，且不依赖对端保留 `warn_info` 不清理。
  3. **参数钩子现成**：乙档 50% 阈值将来 = `vqms_judge_param` 加一行参数即可（§6.2.5），无需现在预留新结构。
- **两个边界（勿混淆）**：
  - **读取层「坏行跳过 + 记日志」闸门照旧**——那是读取鲁棒性（不让整批失败），**不是** #3 策略；属确定轨，照做不受搁置影响。
  - **真实统计上线前仍须定稿**——合规风险（剔除分母抬高合格率）出在「应用策略」那一刻，搁置期间不产生；但**解封时 #3/#5 重新成为前置条件**（与草稿 §2.8 待定稿项一并收口）。

**流程图联动注记**：图B 解码失败节点 `S1` 措辞随落地同步改为「跳过+记日志 + 单独计数 `undecodable_count`（暂定，需合规确认）」（三处：`docs/核心算法流程图/AVC考核核心算法_流程图_v4_0.md`、`..._通俗版_v4_0.md`、`_render/figB_调节合格率.mmd`，纯措辞、流向不变）；**门控前置框暂不画**（门控点未补录、空转，等补录后再在图B 入口补节点）；**图A 免考判关节点不动**（图里已是「包络失败→再判免考」的后置覆盖，与三阶段管线一致——A2 是代码接口切分，算法流向层面无差异）。

## 11. Docker Compose 部署

| 容器 | 镜像/构建 | 端口(host:container) | 依赖 |
|------|-----------|----------------------|------|
| `mysql` | mysql:8.4 | 13306:3306 | — （管理+统计，唯一持久库） |
| `redis` | redis:7 | 16379:6379 | — （RuoYi 引入） |
| `backend` | 本地构建（`RuoYi-Vue-springboot3/Dockerfile`） | 7000:7000 | mysql, redis |
| `nginx` | nginx:stable | 8080:80 → 前端 + /api | backend |

- **MySQL 配置**：`MYSQL_DATABASE`/`MYSQL_ROOT_PASSWORD`/`utf8mb4` 走 `.env`；`command: --character-set-server=utf8mb4 --collation-server=utf8mb4_general_ci`；named volume 持久化 `/var/lib/mysql`；`ry_*.sql` + `quartz.sql` + VQMS 管理表 SQL 挂 `/docker-entrypoint-initdb.d/` 首初始化。
- **数据库账号分离（最小权限）**：`MYSQL_ROOT_PASSWORD` 仅首次初始化（建库建表 + 建应用账号 + 授权）；后端运行时用**专属应用账号**（如 `vqms_app`，`DB_USER`/`DB_PASSWORD` 走 `.env`）。init 脚本末尾：`CREATE USER 'vqms_app'@'%' IDENTIFIED BY '...'; GRANT SELECT,INSERT,UPDATE,DELETE ON ry_vqms.* TO 'vqms_app'@'%'; FLUSH PRIVILEGES;` —— 不授 DDL/GRANT/跨库。RuoYi `application.yml` 主库 datasource 指应用账号，**不填 root**。
- **外部源账号 SELECT-only**：外部源连接用 `GRANT SELECT`-only 只读账号（§5），把 source 层只读从代码约定升级为 DB 层强制。
- **数据备份恢复（外部源是原始数据唯一真相源，尤为关键）**：① 外部源（10.0.0.9 `qheatavchisdb`）的备份责任与周期须与对端确认并留档——VQMS 不复制原始数据，对端丢数据 = 不可恢复；② 主库 MySQL 定期备份（`mysqldump` 或卷快照）+ 恢复演练，覆盖 `sys_*` + VQMS 管理表 + 派生统计。
- `.env` 管理主库连接、Redis、外部源（`source.type=mysql57` + `SOURCE_HOST=10.0.0.9`）、JWT 密钥与过期；**不入库**。
- `backend` 经 `extra_hosts` 或 host 网络访问外部 AVC 数据源（MySQL 5.7 @ 10.0.0.9）。
- Nginx：`/` 托管前端 SPA（build 产物），`/prod-api/` 反代到 `backend:7000`（剥离前缀转发）。

## 12. 落地步骤：确定轨 vs 搁置轨

> 核心：把工程拆两轨。**确定轨**不依赖算法定稿，照常推进；**搁置轨**用接口 + stub 占位，算法定型后填实。合成数据 26 场景见 `tools/avc-data-gen/`。（`VQMS_测试方案_v1_0.md` 已于 2026-08-17 删除待重写——其 Testcontainers 依赖与开发机无 Docker 冲突；过渡期集成测试直连 10.0.0.9 合成库。）

### 12.1 确定轨（现在就能做，不被算法变更推翻）

| # | 工作 | 依据 | 完成标准 |
|---|---|---|---|
| D1 | `source/` 外部只读层：`HisCurveSvReader` 接口 + `Mysql57CurveReader`，读 `his_curve_sv`/`yc_history`/`warn_info` | §5 | 按（时间区间, busbar_num）读通三表；`average_SV`/`plan_SV` 不映射（废值）；坏行跳过+记日志；对合成库 26 场景集成测试通过 |

| D5 | RuoYi 脚手架对接：菜单/权限/字典（含 `vqms_v_grade`）+ 7 个前端页面已有，后端 CRUD 空壳接上 | §9 / §3 | 菜单/权限/perms 生效；空壳 CRUD 页面从前端调通后端 |
| D6 | 前端阶段 1/2/3（品牌已去、骨架已建、电压等级筛选/级联已实施、图表走后端真实数据，不用 mock） | §9.3 | 7 页数据全程走后端 `/vqms/*` API，无 mock；电压等级筛选/级联可用 |

**D4 三步闸门细节（内联，无需回查 v3.4）**：`save_time` 是 `varchar(255)` 带毫秒、无索引，直接 `BETWEEN` 字符串比较会在边界丢行。三步反制：① **放宽边界**——SQL 层用比目标区间前后各扩 1 分钟的字符串范围粗筛（防止边界分钟被字符串比较漏掉）；② **正则校验**——逐行校验 `save_time` 格式（`yyyy-MM-dd HH:mm:ss.SSS`），不匹配 = 坏行，跳过 + 记日志；③ **解析后精确过滤**——合法行解析为时间、就近取整到分钟（§13），在 Java 侧做精确的目标区间过滤，粗筛多读的边界行在此剔除（取整仅在 reader 内用于边界裁剪；reader 对外返回**原始时间戳**，judge 侧窗口对齐由调用方经 D3 做——取整幂等，见 §5 时间契约）。

## 13. 单位规约

VQMS 全项目统一采用以下规范单位，字段、计算、文档、UI 展示均以此为准：

| 量 | 规范单位 | 存储 | 说明 |
|---|---|---|---|
| 电压（`average_SV`/`high_SV`/`low_SV`/`plan_SV`/`nominal_kv`/`tolerance_v`） | **kV** | decimal | 源数据即整数 kV（220kV 母线 `average_SV`≈234）；`tolerance_v` 用 `decimal(10,3)`（1.000/1.500） |
| 无功功率 | **kvar** | decimal | 引用 AVC 原文时照录"万千乏"（1 万千乏 = 10000 kvar） |
| 有功 / 容量 | **kW** | decimal | 引用原文时照录"万千瓦" |
| 合格率 / 投运率 | **%** | decimal | 聚合按发令次数（调节合格率）或分钟数（投运率）加权 |
| 时间（聚合） | **分钟数** | int | 投运率记投运/退出分钟计数；调节合格率记指令计数 |

**单位一致性**：源 SV 字段读入后**不做单位换算**（原值即 kV）。参与比较的电压量必须同单位（kV）。`yc_history` 模拟量按 `yc_point_map.unit` 标注，纳入统计前归一到规范单位。

**时间原则：就近取整到分钟（秒 ≥ 30 进位）**——`his_curve_sv`/`yc_history` 的毫秒精度原始时间戳在任何逐分钟聚合前就近取整到分钟（秒≥30 进位，<30 舍去），是所有判定与汇总的对齐基础；**不要 floor/截断，也不要按原始秒分组**。

**时区**：全项目统一 **北京时间（UTC+8 / `Asia/Shanghai`）**——统计周期边界、UI 展示、`save_time` 解释均以此为准；JVM 默认时区按 `Asia/Shanghai`，不做 UTC 中转再换算。
