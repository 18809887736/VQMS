# VQMS 外部数据源说明

> 依据：VQMS 面向变电站母线电压质量的采集、统计与可视化。系统从外部 AVC 数据源读取母线电压曲线，按日/月/年三个粒度统计电压合格率、超上限率、超下限率与超限时间，提供 Web 看板与 Excel 导出，支撑电压质量监测与考核。
>
> 本文档基于 [`md/外部DB/qheatavchisdb.md`](md/外部DB/qheatavchisdb.md)、[`md/外部DB/QHeatAvcRtdb.md`](md/外部DB/QHeatAvcRtdb.md) 两份源库结构导出整理，配合 [项目规划_v3_1.md](项目规划_v3_1.md) 使用。**第 5 节的待决问题会直接决定 §6.1/§6.2 统计算法的实现方式，落地前必须先拍板。**

---

## 1. 数据源总览

现场实际存在**两个**外部库，性质完全不同：

| 库 | 类型 | 定位 | VQMS 是否读取 |
|---|---|---|---|
| **qheatavchisdb** | MySQL 5.7.44 @ `10.0.0.9:3306` | **历史库**——AVC 装置落盘的分钟级曲线、报警、调节记录 | ✅ **是**，唯一确定的业务数据源（只读） |
| **QHeatAvcRtdb** | SQLite 3.35.5 | AVC 装置本机的**实时值 + 静态配置库**（母线/机组定义、闭锁逻辑、报警定义、计划曲线等） | ⚠️ 待定——**可能**需要读其中的静态阈值配置表（见 §5.2），但不作为曲线数据源 |

两者不是同一类库：`qheatavchisdb` 存的是"发生过什么"（历史流水），`QHeatAvcRtdb` 存的是"系统怎么配置的"（静态参数 + 当前实时值）。规划文档里"外部数据源（10.0.0.9，只读）"specifically 指 `qheatavchisdb`。

## 2. qheatavchisdb（历史库，主数据源）

### 2.1 连接信息

| 项 | 值 |
|---|---|
| Host | `10.0.0.9:3306` |
| Schema | `qheatavchisdb` |
| 版本 | MySQL 5.7.44 |
| 字符集 | `utf8` / `utf8_general_ci`（注意不是 utf8mb4） |
| 访问方式 | 只读，通过 `source/` 层的 `HisCurveSvReader` 接口访问 |

### 2.2 表清单

| 表名 | 用途 | VQMS 当前是否使用 |
|---|---|---|
| **`his_curve_sv`** | 母线电压曲线（核心表，统计口径来源） | ✅ 主要数据源 |
| `his_curve` | 机组无功功率曲线（`generator_num` 维度） | ❌ 暂不使用 |
| `ori_code` | 遥测编码解码表 | ❌ 不考察（已放弃 `plan_SV` 解码，样例值按废值跳过） |
| `warn_info` | 报警历史（母线/机组闭锁、越限告警文本） | ❌ 暂不使用，未来可能用于越限归因 |
| `adjust_info` | AVC 调节记录 | ❌ 暂不使用 |
| `yc_curve` / `yc_history` | 通用遥测曲线 | ❌ 当前**空表** |

### 2.3 `his_curve_sv` 表结构

```sql
CREATE TABLE `his_curve_sv`  (
  `save_time`   varchar(255)  NULL DEFAULT NULL,  -- 采集时间，非 datetime，含毫秒，无时区
  `busbar_num`  bigint(20)    NULL DEFAULT NULL,  -- 母线编号
  `high_SV`     decimal(10,0) NULL DEFAULT NULL,  -- 该分钟采集窗口内电压最大值（观测极值，非合格阈值）
  `low_SV`      decimal(10,0) NULL DEFAULT NULL,  -- 该分钟采集窗口内电压最小值（观测极值，非合格阈值）
  `average_SV`  decimal(10,0) NULL DEFAULT NULL,  -- 该分钟采集窗口内电压均值（VQMS 统计口径的核心字段，见 §4）
  `plan_SV`     decimal(10,0) NULL DEFAULT NULL   -- 调度下发值（AVC 调度下发的目标电压设定值）
) ENGINE = InnoDB CHARACTER SET = utf8 COLLATE = utf8_general_ci;
```

**已确认**：`SV` = 母线电压（Substation/Bus Voltage）。每行记录一个分钟级采集窗口的四元组：`high_SV`/`low_SV` 为窗口内观测到的电压最高/最低值，`average_SV` 为窗口均值——**VQMS 统计口径以 `average_SV` 为准**；`plan_SV` 为 AVC 调度下发的目标电压设定值。`high_SV`/`low_SV` 仅作曲线展示用的窗口摆动范围，**不参与合格率计算**（合格阈值另取，见 §5）。

**结构性约束（不受语义问题影响，可直接按此实现）**：
- `save_time` 是 `varchar(255)`，格式如 `2021-05-07 15:27:57.541`（含毫秒），**无时区**，按 `Asia/Shanghai` 解释；解析失败的行跳过+记日志，不中断批处理。
- **无主键、无索引**——查询侧必须按 `(save_time, busbar_num)` 去重排序。
- **每分钟双写**：每个采集周期为 `busbar_num` 的每个取值各写一行（样例中为 0 和 1），统计时必须按 `busbar_num` 分组，不能整表聚合。
- `plan_SV` 为调度下发值（目标电压设定值）；样例值 `10245` 为废值（测试数据垃圾），判定时**跳过 + 记日志**——不做 `ori_code` 解码、不反推公式。实际运行时 `plan_SV` 为正常目标电压，可直接使用。

### 2.4 样例数据（2021-05-07，稳态测试数据）

```
save_time                    busbar_num  high_SV  low_SV  average_SV  plan_SV
2021-05-07 15:27:57.556      0           300      300     300         10245
2021-05-07 15:27:57.586      1           230      230     230         10245
2021-05-07 15:28:58.113      0           300      300     300         10245
2021-05-07 15:28:58.135      1           230      230     230         10245
```

⚠️ 样例里 `high_SV = low_SV = average_SV` 在整个时间段内恒定不变——这是**退化的稳态测试数据**，无法用来验证越限分支的正确性（窗口极值与均值完全重合，看不出摆动）。**真实波动数据到位前，越限逻辑无法真正验证。**

## 3. QHeatAvcRtdb（实时/配置库，辅助参考）

不作为曲线数据源，但里面有几张表可能是"合格阈值"的真正来源（见 §5.2），先记录下来供讨论：

### 3.1 `BUSBAR`（母线定义）

```
busbarNum  busbarName    vGrade  TargetMAX  TargetMIN  UpLimit  DownLimit
0          220Kv东母线    1       245        220        300      300
1          220Kv西母线    1       245        220        300      300
```

`vGrade` 为电压等级编码：

| vGrade | 电压等级 |
|:------:|:--------:|
| 0 | 500kV |
| 1 | 220kV |

样例只有 2 条 220kV 母线（`vGrade=1`）。**但 `warn_info` 报警文本里出现"500Kv正母线"字样**，说明真实生产站点至少还存在 500kV 母线（`vGrade=0`）——`busbar_num` 的数量、命名、电压等级不能在代码里写死为"只有 0/1 两条 220kV 母线"，需要按 `vGrade` 设计可扩展的母线元数据（不同等级对应不同合格标准）。

### 3.2 `BUSBAR_VRateParameter`（母线电压合格标准，静态配置 — ⚠️ 不参与计算，可忽略）

```
BusbarNum  VString  VRateUpLimit  VRateDownLimit
0          220KV    235.0         232.0
1          220KV    235.0         232.0
```

这看起来是**每条母线一个固定的合格电压区间**（220kV 母线标准 232~235V），与 `his_curve_sv` 逐行数据完全是两个来源。**决定：此表不参与 VQMS 任何计算，可忽略**——合格阈值改由 VQMS 自建管理表维护（见 §5 第 1 条）。

### 3.3 `PLAN_CURVE` / `PLAN_CURVE_31DAY`（分时段目标电压曲线）

```
curveNum  num  start_time_hour  start_time_minute  system_v  system_v_up  system_v_down
1         18   4                15                 510.0     511.0       509.0
```

这是 AVC **自动调节控制**用的分时段目标值 + 窄容差带（±1V 量级），服务于闭环调节，**不是**电压质量合格率统计用的国标/企标区间——数值量级（510 附近）也明显对应另一条更高电压等级（疑似 500kV）母线，与 §3.2 的 220kV 标准不是同一套。

## 4. 字段语义（已确认）

每行 `his_curve_sv` 是一个分钟级采集窗口，四个 SV 字段语义现已明确，**讨论以 `average_SV` 为核心**：

| 字段 | 语义 | VQMS 用途 |
|---|---|---|
| **`average_SV`** | 窗口内电压**均值** | ★ **统计口径核心**——合格率、超限率、超限时间全部基于此值判定 |
| `high_SV` | 窗口内电压**最高观测值** | 仅作曲线展示用的窗口摆动范围，不参与合格率计算 |
| `low_SV` | 窗口内电压**最低观测值** | 同上 |
| `plan_SV` | AVC **调度下发**的目标电压设定值 | AVC 口径下作窄区间中心（`plan_SV` ± 容差）；样例 `10245` 为废值，跳过不解码 |

**关键结论**：`high_SV`/`low_SV` 是同一物理量的观测极值，**不是合格阈值**（佐证：兄弟表 `his_curve` 用相同命名 `high_Q/low_Q/average_Q` 描述无功功率，无功功率无"合格阈值"概念，只能是极值+均值）。因此合格判定的上下限必须另取——这是 §5 第 1 条要拍板的问题。`average_SV` 是唯一参与合格率计算的实测值。

> 注：现有规划 `CLAUDE.md` 里"`average_SV` 对 `[low_SV, high_SV]` 判定"的算法描述基于已被推翻的假设 A，需同步更新为"对静态合格区间判定"。

## 5. 待决问题清单（阻塞 §6.1/§6.2 算法实现）

1. **合格阈值的数据源**（§4 确认 `high_SV`/`low_SV` 非阈值后的核心问题）：`average_SV` 应对哪个区间判定合格？`BUSBAR_VRateParameter` 已排除（§3.2，不参与计算），阈值改由 **VQMS 自建管理表**维护（在 RuoYi 后台配置，运营人员可改）——符合"存储切分铁律"（阈值是管理数据）。待办：① 首批数值从现场标准/国标人工录入；② 设计"阈值变更后历史统计要不要重算"的策略。
2. **母线编号/名称/电压等级不能写死**：至少存在 220kV（`busbar_num 0/1`）和疑似 500kV（`warn_info` 文本佐证）两个电压等级，需设计可扩展的母线元数据（编号→名称→额定电压→合格标准）而非硬编码两条母线。
3. **稳态样例数据无法验证越限分支**：需要一批含真实波动（越上限/越下限）的历史数据用于算法联调和单测，否则 M2 阶段的单元测试只能覆盖"全合格"这一种路径。

> **已确认（不再讨论）**：`high_SV`/`low_SV` = 窗口观测极值（非阈值）；`average_SV` = 统计核心字段；`plan_SV` = 调度下发值（样例 `10245` 为废值，跳过不解码；实际运行按真实值，作 AVC 窄区间中心）。

## 6. 接入设计原则（与 §4/§5 的结论无关，不受影响，可直接执行）

- **只读隔离**：`source/` 层通过 `HisCurveSvReader` 接口访问，方言无关设计，当前实现为 `Mysql57CurveReader`；配置走 `source.type=mysql57|...` + `.env`，切换数据源只改配置。
- **存储切分铁律**：`his_curve_sv` 原始曲线**绝不复制进 VQMS 主库（MySQL 8.4）**；主库只存可重算的派生统计（`voltage_quality_daily/monthly/yearly`）和管理数据。
- **时间解析**：统一在 `source/` 实现层内解析 `varchar` 格式的 `save_time`，按 `Asia/Shanghai`，格式异常的行跳过+记日志。
- **去重排序**：读取时按 `(save_time, busbar_num)` 排序去重，不依赖源表索引（因为没有）。
- **查询粒度**：所有统计和展示均按 `busbar_num` 分组，不跨母线聚合（除非是产品需求明确要求的"全站汇总"视图）。
