## 2. 母线电压合格范围：国标 vs 调度控制目标

现场文档里"电压"二字随处可见，但至少指两件性质不同的事：**电能质量合规线（国标）** 与 **AVC 主动控制目标（调度下发）**。两者数值差一个数量级，对 VQMS 的阈值设计是关键前置，展开辨析。

### 2.1 国家标准合格范围（GB/T 12325-2008）

现行国标《电能质量 供电电压偏差》，按电压等级分档：

| 电压等级 | 允许偏差 |
|----------|----------|
| 35kV 及以上（含 110kV / 220kV / 500kV） | 正、负偏差绝对值之和 ≤ 标称电压的 **10%** |
| 20kV 及以下三相供电 | 标称电压的 **±7%** |
| 220V 单相供电 | 标称电压的 **+7% / −10%** |

对 **220kV 母线**：按国标理论区间为 **198~242kV（±10%）**。这是"电网供电质量考核"用的——衡量该点位电压有没有严重失控、伤害用户设备，属于**兜底红线**，不是精细控制目标。

国标对"电压合格率"的定义直白：**实际运行电压偏差在限值内的累计时间占统计总时长的百分比**。

### 2.2 调度下发指令（AVC 目标值）是另一回事

调度中心下发给 AVC 装置的目标曲线（对应外部库 `PLAN_CURVE` / `his_curve_sv.plan_SV`），追求的不是"不违规"，而是运行在**经济、稳定的最优点**附近——目的是降损、保证无功平衡、给设备留调节裕度。这个目标区间通常比国标宽容线**窄得多**，因为它是"主动控制目标"而非"底线"。

**VQMS 初始阈值（AVC 控制目标口径，按 `vGrade` 分档）**——即"AVC 控制达标率"判定用的合格区间，**以当分钟调度下发指令 `plan_SV` 为中心**，逐分钟随目标值变动：

| vGrade | 电压等级 | 合格区间（初始容差） | 示例 |
|:------:|:--------:|:--------------------:|------|
| 0 | 500kV | `plan_SV` ±500V | 目标 500kV → 499.5 ~ 500.5 kV |
| 1 | 220kV | `plan_SV` ±300V | 目标 222kV → 221.7 ~ 222.3 kV |

即 `|average_SV − plan_SV| ≤ 容差` 算合格（边界算合格）。容差为**初始默认值**，后续由阈值管理表按站点 / 运行工况调整。

> ⚠️ **`plan_SV` 处理（不解码）**：样例值 `10245` 为废值（测试数据垃圾）——不考察 `ori_code` 表、不反推解码公式。实际运行时 `plan_SV` 为 AVC 下发的正常目标电压，AVC 口径按真实值直接计算；真实数据到位前，AVC 口径无法实际运行，且**"不解码即可用"这个假设本身尚未验证**（详见 §4-0）。`plan_SV` 未落在合理量程时，该分钟是否参与考核做成可选策略（默认跳过，见 §5.3）。

外部库 `BUSBAR_VRateParameter` 的 232~235V（220kV 档）窄区间，本质上更像是**装置自身的运行控制目标区间**，而不是国标那种 ±10% 的宽松合规线——两者不是同一个概念，数值差一个数量级。

> 注：v3.1 已决定 `BUSBAR_VRateParameter` **不参与 VQMS 任何计算**（见 [外部数据源.md](外部数据源.md) §3.2）；此处仅借它说明"窄区间"的性质，不代表 VQMS 会读它。

### 2.3 两者的关联链条（闭环）

实际运行是一个闭环：

```
调度中心（潮流计算 / 无功优化）
   │  下发目标曲线（窄区间，PLAN_CURVE / plan_SV）
   ▼
AVC 装置实时采集母线电压
   │  投切电容器 / 调节机组无功，把电压往目标区间拉
   ▼
拉不住或有异常 → 触发告警（warn_info 里"电压越上限/下限闭锁"记录）
   │
   ▼
但只要电压没超【国标合规线 ±10%】
   → 从"电能质量考核"角度依然算合格，只是没达到 AVC 自己的精细控制目标
```

**关键区分（严重程度不同，不可混为一谈）**：

| 情形 | 性质 |
|------|------|
| 没跟上调度目标（超出 AVC 窄区间） | 运行**经济性 / 精细度**问题 |
| 电压不合格（违反国标 ±10%） | **安全合规**问题 |

## 3. 对 VQMS 阈值设计的影响

这个区分直接影响 v3.1 定下的"合格阈值管理表"该填什么数。填哪套，取决于 VQMS 的"电压合格率"统计到底服务谁：

| VQMS 用途 | 阈值口径 | 数值（220kV 例） |
|-----------|----------|------------------|
| 给电网公司做**电能质量考核** | 国标 ±10%（35kV 及以上） | 198~242kV |
| 给现场运维 / **AVC 效果评估** | AVC 控制目标窄区间（以 `plan_SV` 为中心） | `plan_SV` ±300V（220kV档）/ ±500V（500kV档），见 §2.2 |

- **若是前者**：阈值该按国标 ±10% 填，**不该照抄** `BUSBAR_VRateParameter` 的 232~235。
- **若是后者**：232~235 这类窄区间才是对的口径，但这本质上该叫 **"AVC 控制达标率"**，而非"电压合格率"——两个名字混用会让统计结果的解读产生歧义。
- **现实可能需要两套统计并存**：合规率（国标）+ 控制达标率（AVC 目标），分别服务不同受众（电网公司 vs 现场运维）。

> 阈值还需按 `vGrade`（电压等级）分档：500kV / 220kV 的标称电压与合格区间不同，不能全站套同一组数（见 [外部数据源.md](外部数据源.md) §3.1 的 `vGrade` 枚举）。

## 4. 待决问题（v3.2 更新）

> 相对 v3.1 §11，**新增第 0 条（首要、阻塞阈值落地）**；v3.1 的 1~11 条全部沿用，此处不重复。

### 0.（首要）"电压合格率"的口径定义

比"阈值从哪张表读"更根本：

- **工作口径 = AVC 控制效果评估（窄区间）**：由"火电厂 AVC 考核场景"的业务定位推出——"电压合格率"指 AVC 把电压控制在目标窄区间内的达标率。**最终仍需现场 / 客户确认。**
- 结论直接决定：
  1. 阈值管理表填 **AVC 窄区间**容差（500kV ±500V / 220kV ±300V，见 §2.2）；
  2. 是否需要两套统计并存——目前按**单套（控制达标率）**设计，国标 ±10% 合规率按需再加；
  3. 指标命名沿用 **"电压合格率"**（业务方习惯叫法）。
- **依赖真实 `plan_SV`**：样例 `10245` 为废值（跳过，不解码）；实际运行时 `plan_SV` 为正常目标电压，AVC 口径按真实值算窄区间，到位前无法实际运行（见 §2.2）。
  - ⚠️ **真实数据到位后第一件事——验证量程假设**：「不解码」决定依赖一个未验证假设：生产 `plan_SV` 直接就是合理电压、不是编码值。需先抽查真实 `plan_SV` 是否落在合理量程（220kV 档 ~200 出头、500kV 档 ~500，而非又是一个 `10245` 量级）。万一不成立（仍是编码值），AVC 公式直接失效，需回头重新处理编码。

> 其余沿用 v3.1 §11（Redis 已引入、ruoyi-ui 清理、稳态数据验证、时区、大范围导出、凭据管理、若依升级路径、VALUES(col) deprecated 等）。**`plan_SV` 解码项已撤销**——不做 `ori_code` 考察、不反推公式，样例值 `10245` 按废值跳过（见 §2.2）。

## 5. 母线与阈值管理表 DDL（v3.2 新增）

> v3.1 §5.2 只定义了 `voltage_quality_*` 统计表；但统计要跑起来，还得先有「母线元数据」和「阈值」两张管理表——§4 口径已定 AVC，阈值就是「`plan_SV` ± 容差」里的容差。这两张表是「结构先行、数值后填」：DDL 现在就能定，初始数值待现场确认后录入。属于 VQMS 管理数据，落主库 MySQL（与 `sys_*`、`voltage_quality_*` 同库）。

### 5.1 `busbar`（主母线元数据）

```sql
CREATE TABLE `busbar` (
  `busbar_num`    bigint(20)    NOT NULL                COMMENT '主母线编号，对齐 his_curve_sv.busbar_num',
  `busbar_name`   varchar(64)   NOT NULL                COMMENT '母线名称，如 220kV 正母线',
  `v_grade`       tinyint       NOT NULL                COMMENT '电压等级编码：0=500kV, 1=220kV（可扩展，见 外部数据源.md §3.1）',
  `nominal_kv`    decimal(10,3) NOT NULL                COMMENT '标称电压 kV（220.000 / 500.000）；国标 ±10% 区间据此现算',
  `status`        char(1)       NOT NULL DEFAULT '0'    COMMENT '状态：0=正常, 1=停用',
  `create_by`     varchar(64)   DEFAULT ''              COMMENT '创建者',
  `create_time`   datetime      DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_by`     varchar(64)   DEFAULT ''              COMMENT '更新者',
  `update_time`   datetime      DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `remark`        varchar(255)  DEFAULT NULL            COMMENT '备注',
  PRIMARY KEY (`busbar_num`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci COMMENT='VQMS 主母线元数据';

INSERT INTO `busbar` (`busbar_num`, `busbar_name`, `v_grade`, `nominal_kv`) VALUES
```

### 5.2 `busbar_threshold`（阈值，带生效区间，变更不回溯重算）

```sql
CREATE TABLE `busbar_threshold` (
  `threshold_id`    bigint(20)    NOT NULL AUTO_INCREMENT COMMENT '主键',
  `busbar_num`      bigint(20)    NOT NULL                COMMENT '母线编号（逻辑 FK → busbar.busbar_num）',
  `criterion_type`  varchar(8)    NOT NULL DEFAULT 'AVC'  COMMENT '口径：AVC=控制达标率(窄区间，用 tolerance_v)；GB=国标±10%(按 busbar.nominal_kv 现算，tolerance_v 留空)',
  `tolerance_v`     int           DEFAULT NULL            COMMENT 'AVC 容差(伏特)：220kV=300, 500kV=500；GB 口径为空',
  `plan_sv_invalid_policy` varchar(20) NOT NULL DEFAULT 'SKIP' COMMENT 'plan_SV 未落合理量程时考核策略：SKIP=剔除不计(默认) / COUNT_UNQUALIFIED=按不合格计 / FALLBACK=回退标称±容差判一次',
  `effective_from`  date          NOT NULL                COMMENT '生效起始日（含）',
  `effective_to`    date          DEFAULT NULL            COMMENT '生效结束日（含），NULL=至今有效',
  `create_by`       varchar(64)   DEFAULT ''              COMMENT '创建者',
  `create_time`     datetime      DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_by`       varchar(64)   DEFAULT ''              COMMENT '更新者',
  `update_time`     datetime      DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `remark`          varchar(255)  DEFAULT NULL            COMMENT '备注',
  PRIMARY KEY (`threshold_id`),
  KEY `idx_busbar_effective` (`busbar_num`, `effective_from`, `effective_to`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci COMMENT='VQMS 母线电压合格阈值（带生效区间）';

-- 初始数据（AVC 口径，容差按 §2.2 默认）
INSERT INTO `busbar_threshold` (`busbar_num`, `criterion_type`, `tolerance_v`, `effective_from`) VALUES
  (0, 'AVC', 300, '2026-01-01'),
  (1, 'AVC', 300, '2026-01-01');
```

### 5.3 设计说明

- **生效区间 + 不重算**：统计任务按「被统计分钟」所在日期查 `effective_from ≤ 当天 ≤ effective_to(或永远)` 的阈值行——阈值变更只影响之后，历史统计不回溯重算。`idx_busbar_effective` 支撑这个时间旅行查询。
- **`criterion_type` 留双口径**：当前只用 `AVC`（存 `tolerance_v`）；`GB` 预留——若日后要国标合规率并存，插入 `criterion_type='GB'` 行（`tolerance_v` 空，区间 = `busbar.nominal_kv` × [0.9, 1.1] 现算），无需改表结构。
- **AVC 判定公式**（口径=AVC 时）：`|average_SV − plan_SV| ≤ tolerance_v` → 合格；其中 `plan_SV` 来自当分钟 `his_curve_sv` 行，`tolerance_v` 来自本表。
- **plan_SV 废值的考核策略（可配置）**：`plan_SV` 未落在合理量程（废值 / 越限编码，如 `10245`）时，该分钟是否计入电压合格率，由 `busbar_threshold.plan_sv_invalid_policy` 列决定（随阈值行生效，VQMS 自管、**不用 RuoYi `sys_config`**）：
  - `SKIP`（默认）：整行剔除，不计入分子也不计入分母；
  - `COUNT_UNQUALIFIED`：计入分母、不计入分子（按不合格计，惩罚无效 `plan_SV`）；
  - `FALLBACK`：回退到标称电压 ± 容差判一次，仍计入分子 / 分母。

  统计任务按当分钟生效的阈值行取策略分流；无论哪种策略，废值行都记日志。
- **母线维度而非 vGrade 维度**：阈值按 `busbar_num` 存（支持逐条母线覆盖）；同 `vGrade` 的母线容差通常相同（初始数据如此），但允许例外。500kV 母线（`v_grade=0`）待现场补录 `busbar` 行 + 对应 `tolerance_v=500`。
- **物理 FK 不建**：`busbar_threshold.busbar_num` 是逻辑外键，不建物理 FK（`his_curve_sv` 在外部库，跨库 FK 无意义；与 RuoYi 既有表风格一致）。
- **生效区间不重叠（应用层保证，不能裸 INSERT）**：表结构/索引都不阻止同一 `busbar_num` 出现时间重叠的阈值行（DB 难以用普通约束表达"区间不重叠"），一旦重叠，"当天生效的阈值"查询会命中多行、逻辑无法处理。故「新增阈值」须包一层业务逻辑：先查该母线当前生效记录（`effective_to IS NULL` 或含当天），把它的 `effective_to` 闭合到「新记录 `effective_from` 前一天」，再插入新行。整个动作放一个事务里。
- **索引性能备注（非阻塞）**：`idx_busbar_effective (busbar_num, effective_from, effective_to)` 对"某天用哪条阈值"查询（`effective_from <= :day AND (effective_to IS NULL OR effective_to >= :day)`）只有前两列被高效利用——`effective_to` 的 `OR-NULL` 条件破坏索引连续性，退化成按 `busbar_num + effective_from` 缩范围后回表过滤。阈值表通常几十~几百行，无所谓；若意外涨到几十万行（不太可能）再重审查询/索引。

### 5.4 `yc_point_map`（yc_history 遥测点映射，草案）

> `yc_history`（外部库通用遥测曲线）真实运行时有数据，其 `yc_num` 是遥测点编码、`yc_data` 是值——需一张映射表把 `yc_num` 解读成语义。例：`yc_num=3008` → 「主母线号」，某行 `yc_data=0` 即「该时刻主母线号为 0」。

```sql
CREATE TABLE `yc_point_map` (
  `yc_num`      bigint(20)    NOT NULL                COMMENT '遥测点编码，对齐 yc_history.yc_num',
  `point_name`  varchar(64)   NOT NULL                COMMENT '语义名称，如 主母线号',
  `point_type`  varchar(32)   DEFAULT NULL            COMMENT '分类：busbar_id=主母线号指示点 / voltage=电压模拟量 / yx=开关量（0/1 遥信，配 state_1/0_label）',
  `unit`        varchar(32)   DEFAULT NULL            COMMENT '单位（如有，yc 模拟量）',
  `state_1_label`  varchar(32)   DEFAULT NULL            COMMENT 'yx 点值=1 的语义（如 远方/投入）；yc 模拟量留空',
  `state_0_label`  varchar(32)   DEFAULT NULL            COMMENT 'yx 点值=0 的语义（如 就地/退出）；yc 模拟量留空',
  `gate_enabled`   tinyint(1)    NOT NULL DEFAULT 0      COMMENT '该 yx 点是否启用为电压合格率考核门控：1=启用（须 yc_history 真实有该点数据才生效）/ 0=不参与',
  `remark`      varchar(255)  DEFAULT NULL            COMMENT '备注',
  `create_time` datetime      DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` datetime      DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`yc_num`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci COMMENT='yc_history 遥测点编码映射';

-- 初始数据（真实点位：3008 = 220kV 组主母线号指示点）
INSERT INTO `yc_point_map` (`yc_num`, `point_name`, `point_type`, `state_1_label`, `state_0_label`, `gate_enabled`) VALUES
  (3008, '主母线号', 'busbar_id', NULL, NULL, 0);
-- ⚠️ 待现场补录 yc_num 的两个 yx 点（远方就地总、AVC投退），确认 yc_num 后取消注释插入：
-- (<yc_num>, '远方就地总', 'yx', '远方', '就地', 1),
-- (<yc_num>, 'AVC投退',   'yx', '投入', '退出', 1);
```

**查询用法**（点时间查询，取"不晚于统计时刻的最近一条记录"）：

```sql
SELECT yc_data FROM yc_history
WHERE yc_num = 3008 AND yc_time <= :统计时刻
ORDER BY yc_time DESC LIMIT 1;
-- 结果 = 当时的主母线号，用于判定该分钟哪条 busbar_num 是「主母线」，纳入统计范围
```

**yc_history 里的 yx 点（开关量当 yc 存）**

`yc_history` 真实运行时除电压等模拟量（yc）外，还混有**把站级遥信（yx）按 yc 方式存**的点——`yc_data` 取 0/1。用 `point_type='yx'` 标记，语义读 `state_1_label`/`state_0_label`。当前已知两类（yc_num 待现场补录，同 3008 性质）：

| point_name | state_1_label | state_0_label | 统计作用 |
|---|---|---|---|
| 远方就地总 | 远方 | 就地 | 就地模式下 AVC 远方闭环不生效 → 门控 |
| AVC投退 | 投入 | 退出 | AVC 退出时段不计入控制达标率 → 门控 |

**这两个 yx 点是统计口径的门控信号（非电压计算输入）**。是否参与考核由「开关 + 数据存在性」共同决定，以后新上来的 yx 点同理：

| 条件 | 是否门控 |
|---|---|
| `gate_enabled=0`（未启用） | **不参与**——完全不门控，即使 yc_history 有该点数据 |
| `gate_enabled=1` 但 yc_history **无**该 yc_num 数据（点未接入/未采集） | **不参与**——自动跳过（无数据可判） |
| `gate_enabled=1` 且 yc_history **有**该点数据 | **参与**——按值门控，命中则该分钟剔除（默认） |

即「参与 = 启用 ∧ 数据存在」，二者缺一即照常考核、不门控。运行时：统计任务每分钟遍历 `gate_enabled=1` 的 yx 点，先查 yc_history 当分钟是否存在该 `yc_num` 记录——不存在则跳过该点；存在则读值比对 `state_1/0_label`：

- **AVC投退=0（AVC 退出）**：AVC 未参与控制，该分钟**不计入 AVC 控制达标率**分母（性质同 §5.3 `plan_sv_invalid_policy=SKIP`，但成因是"装置退出"而非"目标值废"）。
- **远方就地总=0（就地）**：就地模式下 AVC 远方闭环不生效，默认同上剔除。
- 两者任一命中即剔除（取并集，保守）。

> ⚠️ 命中后的处理口径（剔除 vs 仅标记 vs 照算）暂按"剔除"实现；真实数据到位并与现场确认后，再决定是否提升为可配列（类比 `plan_sv_invalid_policy`）。**预留**：以后还会加别的站级 yx 门控点，统一走 `point_type='yx'` + `state_1/0_label` + `gate_enabled`——填上映射、把 `gate_enabled` 置 1 即自动纳入，无需改表结构或统计代码。

> ⚠️ **待补**：
> 1. `3008` 目前只确认是 220kV 组（`busbar_num 0/1` 那对）的指示点；500kV 组的指示点号待现场补录。
> 2. `yc_history` 现在的导出样本是空表，真实取值是否稳定落在 `{0, 1}`、跳变时间点是否与实际倒闸记录吻合，需等真实数据到位后验证（同 §4-0 的 `plan_SV` 量程验证是同一批性质的待办）。

### 5.5 时间对齐：就近取整到分钟（his_curve_sv / yc_history 共用）

外部库原始记录带毫秒、采样时刻不在整分钟边界（如 `15:27:57.556`）。统计按「分钟」聚合前，需先把每条记录的时间戳**就近取整到分钟**，作为它归属的统计分钟。`his_curve_sv` 与 `yc_history` 两表共用此规则。

**规则**：`秒 < 30 → 归当前分钟；秒 ≥ 30 → 进位到下一分钟`（就近，round half up；精确 `30.000` 边界罕见，按进位处理）。

| 原始时间戳 | 归属分钟 |
|---|---|
| `2021-05-07 15:27:57.556` | **15:28**（57.556 靠近 15:28） |
| `2021-05-07 15:27:57.586` | **15:28** |
| `2021-05-07 15:28:58.113` | **15:29**（58.113 靠近 15:29） |
| `2021-05-07 15:28:58.135` | **15:29** |

- **his_curve_sv**：电压曲线记录按此对齐到分钟；正常每分钟每 `busbar_num` 一条。若对齐后同一分钟同一母线落入多条，需聚合（默认均值，策略待补）。
- **yc_history**：遥测/遥信点同样对齐到分钟。yx 状态点（远方就地/AVC投退）具**阶跃保持**性——某对齐分钟无新记录时，沿用最近一条已对齐记录的值，与 §5.4「取不晚于该分钟的最近一条」一致。
- **两表按对齐分钟 join**：统计某分钟时，`his_curve_sv` 的电压值与 `yc_history` 的 yx 门控状态，统一以「对齐分钟」为键匹配。

> SQL 参考就近取整：`FROM_UNIXTIME(ROUND(UNIX_TIMESTAMP(ts)/60)*60)`；具体在 rollup 落地时依 MySQL 版本实现（v3.1 §6.3 rollup SQL 随之调整）。
