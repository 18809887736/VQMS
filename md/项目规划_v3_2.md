## 1. 项目概述

### 1.1 为什么有 v3.2（v3.1 → v3.2 的定位）

v3.1 把合格阈值定为「VQMS 自建管理表」，但留下一个更根本的问题没回答：**这张表该填什么数？** 现场至少存在两套"电压区间"——国标合格范围（宽松，±10%）和 AVC 调度控制目标（窄区间，如 232~235）——性质完全不同，混用会让"电压合格率"的统计结果产生歧义。

本版本的核心增量：辨析这两套区间的性质差异与关联链条，并把它上升为 §4 的**首要待决问题**——比"阈值从哪张表读"更根本。

## 2. 母线电压合格范围：国标 vs 调度控制目标

现场文档里"电压"二字随处可见，但至少指两件性质不同的事：**电能质量合规线（国标）** 与 **AVC 主动控制目标（调度下发）**。两者数值差一个数量级，对 VQMS 的阈值设计是关键前置，展开辨析。

### 2.1 国家标准合格范围（GB/T 12325-2008）

现行国标《电能质量 供电电压偏差》，按电压等级分档：

| 电压等级 | 允许偏差 |
|----------|----------|
| 35kV 及以上（含 110kV / 220kV / 500kV） | 正、负偏差绝对值之和 ≤ 标称电压的 **10%** |
| 20kV 及以下三相供电 | 标称电压的 **±7%** |
| 220V 单相供电 | 标称电压的 **+7% / −10%** |

对 **220kV 母线**：按国标理论区间为 **198~242kV（±10%）**。这是"电网供电质量考核"用的——衡量该点位电压有没有严重失控、伤害用户设备，属于**兜底红线**，不是精细控制目标。

国标对"电压合格率"的定义直白：**实际运行电压偏差在限值内的累计时间占统计总时长的百分比**。

### 2.2 调度下发指令（AVC 目标值）是另一回事

调度中心下发给 AVC 装置的目标曲线（对应外部库 `PLAN_CURVE` / `his_curve_sv.plan_SV`），追求的不是"不违规"，而是运行在**经济、稳定的最优点**附近——目的是降损、保证无功平衡、给设备留调节裕度。这个目标区间通常比国标宽容线**窄得多**，因为它是"主动控制目标"而非"底线"。

**VQMS 初始阈值（AVC 控制目标口径，按 `vGrade` 分档）**——即"AVC 控制达标率"判定用的合格区间，**以当分钟调度下发指令 `plan_SV` 为中心**，逐分钟随目标值变动：

| vGrade | 电压等级 | 合格区间（初始容差） | 示例 |
|:------:|:--------:|:--------------------:|------|
| 0 | 500kV | `plan_SV` ±500V | 目标 500kV → 499.5 ~ 500.5 kV |
| 1 | 220kV | `plan_SV` ±300V | 目标 222kV → 221.7 ~ 222.3 kV |

即 `|average_SV − plan_SV| ≤ 容差` 算合格（边界算合格）。容差为**初始默认值**，后续由阈值管理表按站点 / 运行工况调整。

> ⚠️ **`plan_SV` 处理（不解码）**：样例值 `10245` 为废值（测试数据垃圾）——不考察 `ori_code` 表、不反推解码公式。实际运行时 `plan_SV` 为 AVC 下发的正常目标电压，AVC 口径按真实值直接计算；真实数据到位前，AVC 口径无法实际运行，且**"不解码即可用"这个假设本身尚未验证**（详见 §4-0）。`plan_SV` 未落在合理量程时，该分钟是否参与考核做成可选策略（默认跳过，见 §5.3）。

外部库 `BUSBAR_VRateParameter` 的 232~235V（220kV 档）窄区间，本质上更像是**装置自身的运行控制目标区间**，而不是国标那种 ±10% 的宽松合规线——两者不是同一个概念，数值差一个数量级。

> 注：v3.1 已决定 `BUSBAR_VRateParameter` **不参与 VQMS 任何计算**（见 [外部数据源.md](外部数据源.md) §3.2）；此处仅借它说明"窄区间"的性质，不代表 VQMS 会读它。

### 2.3 两者的关联链条（闭环）

实际运行是一个闭环：

```
调度中心（潮流计算 / 无功优化）
   │  下发目标曲线（窄区间，PLAN_CURVE / plan_SV）
   ▼
AVC 装置实时采集母线电压
   │  投切电容器 / 调节机组无功，把电压往目标区间拉
   ▼
拉不住或有异常 → 触发告警（warn_info 里"电压越上限/下限闭锁"记录）
   │
   ▼
但只要电压没超【国标合规线 ±10%】
   → 从"电能质量考核"角度依然算合格，只是没达到 AVC 自己的精细控制目标
```

**关键区分（严重程度不同，不可混为一谈）**：

| 情形 | 性质 |
|------|------|
| 没跟上调度目标（超出 AVC 窄区间） | 运行**经济性 / 精细度**问题 |
| 电压不合格（违反国标 ±10%） | **安全合规**问题 |

## 3. 对 VQMS 阈值设计的影响

这个区分直接影响 v3.1 定下的"合格阈值管理表"该填什么数。填哪套，取决于 VQMS 的"电压合格率"统计到底服务谁：

| VQMS 用途 | 阈值口径 | 数值（220kV 例） |
|-----------|----------|------------------|
| 给电网公司做**电能质量考核** | 国标 ±10%（35kV 及以上） | 198~242kV |
| 给现场运维 / **AVC 效果评估** | AVC 控制目标窄区间（以 `plan_SV` 为中心） | `plan_SV` ±300V（220kV档）/ ±500V（500kV档），见 §2.2 |

- **若是前者**：阈值该按国标 ±10% 填，**不该照抄** `BUSBAR_VRateParameter` 的 232~235。
- **若是后者**：232~235 这类窄区间才是对的口径，但这本质上该叫 **"AVC 控制达标率"**，而非"电压合格率"——两个名字混用会让统计结果的解读产生歧义。
- **现实可能需要两套统计并存**：合规率（国标）+ 控制达标率（AVC 目标），分别服务不同受众（电网公司 vs 现场运维）。

> 阈值还需按 `vGrade`（电压等级）分档：500kV / 220kV 的标称电压与合格区间不同，不能全站套同一组数（见 [外部数据源.md](外部数据源.md) §3.1 的 `vGrade` 枚举）。

## 4. 待决问题（v3.2 更新）

> 相对 v3.1 §11，**v3.2 新增第 0 条（首要、阻塞阈值落地）与第 1 条（外部源 `his_curve_sv` 先天缺陷）**；v3.1 原 1~11 条仍有效（见 v3.1 §11），此处不重复，本节只列 v3.2 新增项。

### 0.（首要）"电压合格率"的口径定义

比"阈值从哪张表读"更根本：

- **工作口径 = AVC 控制效果评估（窄区间）**：由"火电厂 AVC 考核场景"的业务定位推出——"电压合格率"指 AVC 把电压控制在目标窄区间内的达标率。**最终仍需现场 / 客户确认。**
- 结论直接决定：
  1. 阈值管理表填 **AVC 窄区间**容差（500kV ±500V / 220kV ±300V，见 §2.2）；
  2. 是否需要两套统计并存——目前按**单套（控制达标率）**设计，国标 ±10% 合规率按需再加；
  3. 指标命名沿用 **"电压合格率"**（业务方习惯叫法）。
- **依赖真实 `plan_SV`**：样例 `10245` 为废值（跳过，不解码）；实际运行时 `plan_SV` 为正常目标电压，AVC 口径按真实值算窄区间，到位前无法实际运行（见 §2.2）。
  - ⚠️ **真实数据到位后第一件事——验证量程假设**：「不解码」决定依赖一个未验证假设：生产 `plan_SV` 直接就是合理电压、不是编码值。需先抽查真实 `plan_SV` 是否落在合理量程（220kV 档 ~200 出头、500kV 档 ~500，而非又是一个 `10245` 量级）。万一不成立（仍是编码值），AVC 公式直接失效，需回头重新处理编码。

> 其余沿用 v3.1 §11（Redis 已引入、ruoyi-ui 清理、稳态数据验证、时区、大范围导出、凭据管理、若依升级路径、VALUES(col) deprecated 等）。**`plan_SV` 解码项已撤销**——不做 `ori_code` 考察、不反推公式，样例值 `10245` 按废值跳过（见 §2.2）。

### 1. 外部源 `his_curve_sv` 先天缺陷（2026-08-06 深挖真实建表语句新发现）

翻 `his_curve_sv` 真实 DDL，确认两处比文档此前描述更严重的缺陷——**都不是 VQMS 设计错，是外部只读源本身的先天缺陷**，此前设计一直默认它能被正常查询，深挖建表语句才暴露：

**① `save_time` 是 `varchar(255)`、无任何格式约束**：`WHERE save_time >= … AND … < …` 是**字符串范围比较**，只有在「全表每一行都零填充 ISO 格式（`YYYY-MM-DD HH:MM:SS[.fff]`）」时才恰好等价于时间比较——样例数据恰好规矩，但这是数据巧合、不是数据库保证。生产跑几年只要出现过一次异常写入（某固件版本漏补零写成 `'2021-5-7 9:5:3'`、或混入别的时间格式），字符串排序就和真实时间脱节，范围过滤会**静默漏/多取数据且不报错**——平时看不出来，跑到那条脏数据所在日期才诡异地对不上账。

- **VQMS 侧处置（已定，不阻塞）——「放宽边界 + 格式校验 + 解析后精确过滤」三步闸门**（见 §5.7.3 ①-a）：只取数后校验**只能兜「取到了但脏」的行，兜不住「该取的因格式异常被字符串排序挤出边界、在 DB 层就被无声丢弃」的行**——后者连日志都没有，更隐蔽。利用「全表无索引 → range 查询本就全表扫描、WHERE 收窄不省扫描成本」这一点，**故意把 SQL-1/SQL-2 日期边界放宽安全余量**（默认 ±1 天），把「是否属于当天」交给 Java 侧**解析后的真实时间值**权威判断：放宽结果集先过格式正则（脏行记日志+标缺，走数据关 SKIP），干净行解析后按真实时间精确过滤，余量行丢弃（归相邻日 rollup，按真实时间不重复计）。把最危险的「DB 层静默丢数」降级为「闸门可见、可记日志」的可追踪失败；顺带修复跨天 yx 阶跃在日边界被截断的问题。
- **残留（需知晓，非 100% catch）**：错位幅度超过余量的恶性脏写（如月位漏补零 `'2021-5-7'` 字面排序远离 `'2021-05-0x'`，±1 天捞不回）仍可能在 DB 层丢失——靠调大余量（如 ±1 月）或对「当日返回行数远低于预期」做计数告警兜底。核心收益是 **DB 边界不再当正确性脆点**，而非保证不丢。

**② 全表无主键、无任何索引（连自增 id 都没有）**：SQL-1 那条「取某一天」的范围查询，无论表里积了多少年历史，每次都**全表扫描**再筛——样例数据量小无感，但这是持续写入的历史表，rollup 会**越跑越慢，且是「一开始无感、几个月后突然变慢」的隐蔽退化**。

- **VQMS 侧处置（待现场答复，非阻塞但需跟踪）**：
  - **(a) 优先向现场确认**：能否在 `save_time` 列加一个普通索引？只读方也可能愿意配合——索引不影响其写入逻辑，查询却能从全表扫描变索引定位。最优解。
  - **(b) 若现场不能加索引**：rollup 日调度须做**耗时监控**（单组单日取数 + 聚合耗时随 `his_curve_sv` 行数增长的曲线），一旦明显上扬即启用兜底——定期归档/清理过旧数据，或 VQMS 自建按时间索引的**镜像表**（落主库，带主键 + `save_time` 索引，ingestion 增量同步）。

## 5. 母线与阈值管理表 DDL（v3.2 新增）

### 5.1.1 `busbar_group`（母线组——主母线判定单元）

> ⚠️ **命名消歧**：本表是 **VQMS 自建的 `busbar_group`**（核心配置表）；与外部库 `QHeatAvcRtdb.BUSBAR_GROUP`（大写、**废表不读**，见 §6）只是同名、毫无关系。`group_num` 仅"参考对齐"外部 `BUSBAR.GroupNum`，非物理 FK。

之前把「主母线号」硬编码在 `yc_num=3008` 一个点号上、且只在"从未有数据"时兜底为 0，存在三个缺口：**A** 单点故障/断流无兜底、**C** 数据新鲜度无上限、**B** 全站一套逻辑无法按组独立（500kV 组没接入就被 220kV 硬编码静默忽略）。本表把「指示点 + 陈旧窗口 + 兜底值」统一挂到**组**上，一次解决 A/B/C。

```sql
CREATE TABLE `busbar_group` (
  `group_num`               bigint(20)   NOT NULL                COMMENT '母线组编号，参考对齐 QHeatAvcRtdb.BUSBAR.GroupNum（非物理FK；外部 BUSBAR_GROUP 废表不读）',
  `group_name`              varchar(64)  NOT NULL                COMMENT '组名，如 220kV母线组',
  `v_grade`                 tinyint      NOT NULL                COMMENT '电压等级编码，同 busbar.v_grade',
  `main_indicator_yc_num`   bigint(20)   DEFAULT NULL            COMMENT '该组"当前主母线号"指示点，对齐 yc_history.yc_num；未接入前为空',
  `default_main_busbar_num` bigint(20)   DEFAULT NULL            COMMENT '指示点不可用(无记录/超陈旧窗口)时的兜底主母线号；NULL=不兜底，整组该分钟剔除。占位约定，非物理结论',
  `max_staleness_minutes`   int          NOT NULL DEFAULT 30     COMMENT '指示点陈旧窗口(分钟)：最近一条记录距统计时刻超过此值即视为不可用',
  `remark`                  varchar(255) DEFAULT NULL            COMMENT '备注',
  `create_time`             datetime     DEFAULT CURRENT_TIMESTAMP,
  `update_time`             datetime     DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`group_num`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci COMMENT='VQMS 母线组（主母线判定单元）';

-- 初始数据：220kV 组已知，500kV 组占位待补
INSERT INTO `busbar_group` (`group_num`, `group_name`, `v_grade`, `main_indicator_yc_num`, `default_main_busbar_num`, `max_staleness_minutes`) VALUES
  (0, '220kV母线组', 1, 3008, 0, 30),
  (1, '500kV母线组', 0, NULL, NULL, 30);  -- 指示点号待现场补录，补录前该组不参与统计
```

`busbar.group_num`（§5.1）把每条物理母线归到组；判定主母线时**按组**查该组的 `main_indicator_yc_num`：

```sql
-- 第一步：取该组指示点不晚于统计时刻的最近一条记录
SELECT yc_data, yc_time FROM yc_history
WHERE yc_num = :group.main_indicator_yc_num AND yc_time <= :统计时刻
ORDER BY yc_time DESC LIMIT 1;
-- 第二步：校验取到的 yc_data 是否为该组「在用」的合法母线号（status='0'）
SELECT COUNT(*) FROM busbar
WHERE group_num = :group_num AND busbar_num = :yc_data AND status = '0';
-- 结果 = 0 → 不可用（非法值 或 母线已停用），按下表兜底/剔除
```

拿到结果后按以下顺序判定**该组该分钟**的主母线号：

| 情况 | 处理 |
|---|---|
| `main_indicator_yc_num` 本身为空（组未配指示点，如 500kV 组现在） | 该组该分钟**整体不参与统计** |
| 查无记录（从未有数据） | 走 `default_main_busbar_num`；若也为 NULL → **无主母线（空档，不计 total/excluded，见 §5.7.3 层 0）** |
| 有记录，但 `统计时刻 − yc_time > max_staleness_minutes`（断流/陈旧） | 同上，走 `default_main_busbar_num`；NULL → **无主母线（空档，不计 total/excluded，见 §5.7.3 层 0）** |
| 有记录、新鲜，但 `yc_data` 不是该组一条在用母线（`status='0'`）——非法值或已停用 | 同上，走 `default_main_busbar_num`；NULL → **无主母线（空档，不计 total/excluded，见 §5.7.3 层 0）** |
| 有记录、新鲜、且 `yc_data` 是该组合法母线号 | 主母线号 = `yc_data` |

三种「不可用」情形（无记录 / 陈旧 / 非法值）统一收敛到**同一兜底出口**，实现上合并成一次判断、不必写三段重复逻辑：

```text
若 (无记录) 或 (陈旧) 或 (yc_data 不在该组合法母线号集合内)：
    若 default_main_busbar_num 非空 → 主母线号 = default_main_busbar_num
    否则 → 该组该分钟无主母线（空档，不计入任何母线 total/excluded）
否则：
    主母线号 = yc_data
```

「不可用」就此成为完整的三态穷举（无记录、陈旧、非法值），不再有未覆盖的失败模式。缺口的落点：

- **A（单点故障/断流无兜底）** ✅：「从未有数据」+「断流陈旧」两种情况都被 `max_staleness_minutes` 统一捕获，不再只覆盖"从未有数据"。
- **C（新鲜度无上限）** ✅：`max_staleness_minutes` 就是上限，每组可独立配（500kV 与 220kV 上报频率不同可设不同容差）。
- **B（全站唯一 vs 按组独立）** ✅：表本身按组建。500kV 组指示点为 NULL 即"未接入、不参与"，而非被 220kV 硬编码逻辑静默忽略；现场给了指示点号，一句 `UPDATE` 即接入，不改代码。
- **非法值/已停用（指示点返回的母线号不属于本组在用母线）** ✅：与"无记录""陈旧"合并进同一个兜底/剔除出口，无需额外状态，判定逻辑保持单一出口。

> `default_main_busbar_num=0`（220kV 组）是沿用前述讨论的**占位约定**、非物理结论；500kV 组留空（语义=不兜底、直接剔除）。真实取值待现场确认。

### 5.2 `busbar_threshold`（阈值，带生效区间，变更不回溯重算）

```sql
CREATE TABLE `busbar_threshold` (
  `threshold_id`    bigint(20)    NOT NULL AUTO_INCREMENT COMMENT '主键',
  `busbar_num`      bigint(20)    NOT NULL                COMMENT '母线编号（逻辑 FK → busbar.busbar_num）',
  `criterion_type`  varchar(8)    NOT NULL DEFAULT 'AVC'  COMMENT '口径：AVC=控制达标率(窄区间，用 tolerance_v)；GB=国标±10%(按 busbar.nominal_kv 现算，tolerance_v 留空)',
  `tolerance_v`     int           DEFAULT NULL            COMMENT 'AVC 容差(伏特)：220kV=300, 500kV=500；GB 口径为空',
  `plan_sv_invalid_policy` varchar(20) NOT NULL DEFAULT 'SKIP' COMMENT 'plan_SV 未落合理量程时考核策略：SKIP=剔除不计(默认) / COUNT_UNQUALIFIED=按不合格计 / FALLBACK=回退标称±容差判一次',
  `effective_from`  date          NOT NULL                COMMENT '生效起始日（含）',
  `effective_to`    date          DEFAULT NULL            COMMENT '生效结束日（含），NULL=至今有效',
  `create_by`       varchar(64)   DEFAULT ''              COMMENT '创建者',
  `create_time`     datetime      DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_by`       varchar(64)   DEFAULT ''              COMMENT '更新者',
  `update_time`     datetime      DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `remark`          varchar(255)  DEFAULT NULL            COMMENT '备注',
  PRIMARY KEY (`threshold_id`),
  KEY `idx_busbar_effective` (`busbar_num`, `effective_from`, `effective_to`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci COMMENT='VQMS 母线电压合格阈值（带生效区间）';

-- 初始数据（AVC 口径，容差按 §2.2 默认）
INSERT INTO `busbar_threshold` (`busbar_num`, `criterion_type`, `tolerance_v`, `effective_from`) VALUES
  (0, 'AVC', 300, '2026-01-01'),
  (1, 'AVC', 300, '2026-01-01');
```

### 5.3 设计说明

- **生效区间 + 不重算**：统计任务按「被统计分钟」所在日期查 `effective_from ≤ 当天 ≤ effective_to(或永远)` 的阈值行——阈值变更只影响之后，历史统计不回溯重算。`idx_busbar_effective` 支撑这个时间旅行查询。
- **`criterion_type` 留双口径**：当前只用 `AVC`（存 `tolerance_v`）；`GB` 预留——若日后要国标合规率并存，插入 `criterion_type='GB'` 行（`tolerance_v` 空，区间 = `busbar.nominal_kv` × [0.9, 1.1] 现算），无需改表结构。
- **AVC 判定公式**（口径=AVC 时）：`|average_SV − plan_SV| ≤ tolerance_v` → 合格；其中 `plan_SV` 来自当分钟 `his_curve_sv` 行，`tolerance_v` 来自本表。
- **plan_SV 废值的考核策略（可配置）**：`plan_SV` 未落在合理量程（废值 / 越限编码，如 `10245`）时，该分钟是否计入电压合格率，由 `busbar_threshold.plan_sv_invalid_policy` 列决定（随阈值行生效，VQMS 自管、**不用 RuoYi `sys_config`**）：
  - `SKIP`（默认）：整行剔除，不计入分子也不计入分母；
  - `COUNT_UNQUALIFIED`：计入分母、不计入分子（按不合格计，惩罚无效 `plan_SV`）；
  - `FALLBACK`：回退到标称电压 ± 容差判一次，仍计入分子 / 分母。

  统计任务按当分钟生效的阈值行取策略分流；无论哪种策略，废值行都记日志。
- **母线维度而非 vGrade 维度**：阈值按 `busbar_num` 存（支持逐条母线覆盖）；同 `vGrade` 的母线容差通常相同（初始数据如此），但允许例外。500kV 母线（`v_grade=0`）待现场补录 `busbar` 行 + 对应 `tolerance_v=500`。
- **物理 FK 不建**：`busbar_threshold.busbar_num` 是逻辑外键，不建物理 FK（`his_curve_sv` 在外部库，跨库 FK 无意义；与 RuoYi 既有表风格一致）。
- **生效区间不重叠（应用层保证，不能裸 INSERT）**：表结构/索引都不阻止同一 `busbar_num` 出现时间重叠的阈值行（DB 难以用普通约束表达"区间不重叠"），一旦重叠，"当天生效的阈值"查询会命中多行、逻辑无法处理。故「新增阈值」须包一层业务逻辑：先查该母线当前生效记录（`effective_to IS NULL` 或含当天），把它的 `effective_to` 闭合到「新记录 `effective_from` 前一天」，再插入新行。整个动作放一个事务里。
- **索引性能备注（非阻塞）**：`idx_busbar_effective (busbar_num, effective_from, effective_to)` 对"某天用哪条阈值"查询（`effective_from <= :day AND (effective_to IS NULL OR effective_to >= :day)`）只有前两列被高效利用——`effective_to` 的 `OR-NULL` 条件破坏索引连续性，退化成按 `busbar_num + effective_from` 缩范围后回表过滤。阈值表通常几十~几百行，无所谓；若意外涨到几十万行（不太可能）再重审查询/索引。

### 5.4 `yc_point_map`（yc_history 遥测点映射，草案）

> `yc_history`（外部库通用遥测曲线）真实运行时有数据，其 `yc_num` 是遥测点编码、`yc_data` 是值——需一张映射表把 `yc_num` 解读成语义。例：`yc_num=3008` → 「主母线号」，某行 `yc_data=0` 即「该时刻主母线号为 0」。

```sql
CREATE TABLE `yc_point_map` (
  `yc_num`      bigint(20)    NOT NULL                COMMENT '遥测点编码，对齐 yc_history.yc_num',
  `point_name`  varchar(64)   NOT NULL                COMMENT '语义名称，如 主母线号',
  `point_type`  varchar(32)   DEFAULT NULL            COMMENT '分类：busbar_id=主母线号指示点 / voltage=电压模拟量 / yx=开关量（0/1 遥信，配 state_1/0_label）',
```

**查询用法**（点时间查询，取"不晚于统计时刻的最近一条记录"）：

```sql
-- 点查询示意：取不晚于统计时刻的最近一条记录（写法）
SELECT yc_data, yc_time FROM yc_history
WHERE yc_num = :yc_num AND yc_time <= :统计时刻
ORDER BY yc_time DESC LIMIT 1;
```
> 「主母线号」的完整判定（按组 `main_indicator_yc_num` + 陈旧窗口 + 兜底值）已迁移到 **§5.1.1 `busbar_group`**，不再硬编码 `3008`、也不在此处兜底。`yc_point_map` 里的 `3008` 仅保留"语义映射"（3008=主母线号指示点）。

**yc_history 里的 yx 点（开关量当 yc 存）**

`yc_history` 真实运行时除电压等模拟量（yc）外，还混有**把站级遥信（yx）按 yc 方式存**的点——`yc_data` 取 0/1。用 `point_type='yx'` 标记，语义读 `state_1_label`/`state_0_label`。当前已知两类（yc_num 待现场补录，同 3008 性质）：

| point_name | state_1_label | state_0_label | 统计作用 |
|---|---|---|---|
| 远方就地总 | 远方 | 就地 | 就地模式下 AVC 远方闭环不生效 → 门控 |
| AVC投退 | 投入 | 退出 | AVC 退出时段不计入控制达标率 → 门控 |

**这两个 yx 点是统计口径的门控信号（非电压计算输入）**。是否参与考核由「开关 + 数据存在性」共同决定，以后新上来的 yx 点同理：

| 条件 | 是否门控 |
|---|---|
| `gate_enabled=0`（未启用） | **不参与**——完全不门控，即使 yc_history 有该点数据 |
| `gate_enabled=1` 但 yc_history **无**该 yc_num 数据（点未接入/未采集） | **不参与**——自动跳过（无数据可判） |
| `gate_enabled=1` 且 yc_history **有**该点数据 | **参与**——按值门控，命中则该分钟剔除（默认） |

即「参与 = 启用 ∧ 数据存在」，二者缺一即照常考核、不门控。运行时：统计任务每分钟遍历 `gate_enabled=1` 的 yx 点，先查 yc_history 当分钟是否存在该 `yc_num` 记录——不存在则跳过该点；存在则读值比对 `state_1/0_label`：

- **AVC投退=0（AVC 退出）**：AVC 未参与控制，该分钟**不计入 AVC 控制达标率**分母（性质同 §5.3 `plan_sv_invalid_policy=SKIP`，但成因是"装置退出"而非"目标值废"）。
- **远方就地总=0（就地）**：就地模式下 AVC 远方闭环不生效，默认同上剔除。
- 两者任一命中即剔除（取并集，保守）。

> ⚠️ 命中后的处理口径（剔除 vs 仅标记 vs 照算）暂按"剔除"实现；真实数据到位并与现场确认后，再决定是否提升为可配列（类比 `plan_sv_invalid_policy`）。**预留**：以后还会加别的站级 yx 门控点，统一走 `point_type='yx'` + `state_1/0_label` + `gate_enabled`——填上映射、把 `gate_enabled` 置 1 即自动纳入，无需改表结构或统计代码。

> ⚠️ **待补**：
> 1. `3008` 目前只确认是 220kV 组（`busbar_num 0/1` 那对）的指示点；500kV 组的指示点号待现场补录。
> 2. `yc_history` 现在的导出样本是空表，真实取值是否稳定落在 `{0, 1}`、跳变时间点是否与实际倒闸记录吻合，需等真实数据到位后验证（同 §4-0 的 `plan_SV` 量程验证是同一批性质的待办）。

### 5.5 时间对齐：就近取整到分钟（his_curve_sv / yc_history 共用）

外部库原始记录带毫秒、采样时刻不在整分钟边界（如 `15:27:57.556`）。统计按「分钟」聚合前，需先把每条记录的时间戳**就近取整到分钟**，作为它归属的统计分钟。`his_curve_sv` 与 `yc_history` 两表共用此规则。

**规则**：`秒 < 30 → 归当前分钟；秒 ≥ 30 → 进位到下一分钟`（就近，round half up；精确 `30.000` 边界罕见，按进位处理）。

| 原始时间戳 | 归属分钟 |
|---|---|
| `2021-05-07 15:27:57.556` | **15:28**（57.556 靠近 15:28） |
| `2021-05-07 15:27:57.586` | **15:28** |
| `2021-05-07 15:28:58.113` | **15:29**（58.113 靠近 15:29） |
| `2021-05-07 15:28:58.135` | **15:29** |

- **采集间隔不固定**：样例约 60s/条，实际可能更短（<60s → 一个对齐分钟落入多条）、更长（>60s → 某些对齐分钟无记录）且不均匀。考核粒度仍是「对齐分钟」，按下面两条收敛（电压）+ 一条阶跃保持（yx）。
- ⚠️ **`save_time` 是 `varchar`、无主键/无索引（外部源先天缺陷，详见 §4 待决第 1 条）**：① `WHERE save_time >= … AND … < …` 是**字符串范围比较**，单条脏写（漏补零 `'2021-5-7 9:5:3'`、混入别的时间格式）会让边界行在 DB 层**静默丢失**且不报错；rollup 用「放宽边界 + 格式校验 + 解析后精确过滤」三步闸门反制（见 §5.7.3 ①-a）。② 无索引 = 每日 rollup **全表扫描**，随历史增长变慢——属外部源缺陷，需向现场确认能否加索引 / 否则兜底（见 §4 第 1 条）。
- **his_curve_sv 多条 → 聚合**：同一（对齐分钟 × `busbar_num`）落入多条时，`average_SV` 取**算术平均**，`plan_SV` 取该分钟**末条**（目标值短期不变；多条不同取末值并记日志）——聚合后得到该分钟该母线的**唯一代表记录**。
- **his_curve_sv 缺条 → SKIP**：某（对齐分钟 × `busbar_num`）无记录（间隔>60s 或漏采）→ 该分钟该母线**无电压样本**，进 §5.7.2 层 2 数据关按 `plan_sv_invalid_policy=SKIP` 剔除（计 `excluded`）。电压是瞬时量、**不阶跃保持**。
- **yc_history（指示点 + 门控 yx）→ 阶跃保持**：所有 yx 统一取「不晚于该对齐分钟的**最近一条**」（`yc_time <= t ORDER BY yc_time DESC LIMIT 1`），不受采集间隔影响——yx 是开关状态量、天然持续到下次变化，阶跃保持语义正确（区别于电压瞬时性）。与 §5.1.1 指示点、§5.4 门控一致。
- **聚合后视图 join**：his_curve_sv 先按上述规则聚合/标缺到「（对齐分钟 × busbar_num）唯一代表记录」，yc_history 取定最近 yx 值，两表再以「对齐分钟」为键合并。**不是原始行等值 join**——间隔不固定时原始行 0/1/多条都会破坏直接 join。仍假设两表**同步写入**（同采集周期都落盘、无错位），故无需时间窗口容差。

> SQL 参考就近取整：`FROM_UNIXTIME(ROUND(UNIX_TIMESTAMP(ts)/60)*60)`；具体在 rollup 落地时依 MySQL 版本实现（v3.1 §6.3 rollup SQL 随之调整）。

### 5.6 计量点与电压合格率统计模型

§5.2~§5.5 分别给出阈值表（§5.2）、判定公式（§5.3）、yx 门控（§5.4）、时间对齐（§5.5）。本节把它们组装成「计量点 → 合格与否 → 合格率」的统一模型，明确考核粒度。

**(1) 计量点粒度 =（对齐分钟 × 主母线）**

一个计量点 =「某个对齐分钟」×「某条主母线」。主母线由 **§5.1.1 `busbar_group`** 按组判定（指示点 + 陈旧窗口 + 兜底，不再硬编码 `3008`）——即该分钟电网上充当「主母线」的那一条。**汇齐该计量点在该时刻的全部可查数据**后，给出**一个**合格与否判定：

| 数据来源 | 字段 | 在判定中的作用 |
|---|---|---|
| `his_curve_sv` | `average_SV`、`plan_SV` | 代入 §5.3 合格公式 |
| `yc_history` | 远方就地总、AVC投退 | §5.4 门控：决定该点是否参与考核 |

**(2) 单个计量点的判定流程**（顺序短路，终态 ∈ {合格, 不合格, 剔除}）：

1. **门控关（§5.4）**：该分钟站级 yx 门控点命中（`AVC投退=0` 或 `远方就地总=0`，且点存在、`gate_enabled=1`）→ **剔除**（不计分子分母）。
2. **数据关（§5.3）**：`his_curve_sv` 该分钟该母线缺值，或 `plan_SV` 为废值 → 按 `plan_sv_invalid_policy` 分流（SKIP 剔除 / COUNT_UNQUALIFIED 不合格 / FALLBACK 回退判一次）。
3. **合格关（§5.3）**：`|average_SV − plan_SV| ≤ tolerance_v` → **合格**，否则 **不合格**。

> ⚠️ **当前实现状态（D 文档同步）**：远方就地总 / AVC投退 两个 yx 点的 `yc_num` 尚未从现场拿到（§5.4 仍是占位注释），`gate_enabled` 均为 0——**门控关当前空转，不会真正剔除任何计量点**。等两个点位补录并置 `gate_enabled=1` 后才生效；在此之前，判定实际只跑「数据关 + 合格关」两步。与 §5.4「⚠️ 待补」对齐。

**(3) 电压合格率 = 合格计量点数 ÷ 参与考核计量点数**

```
电压合格率 = 合格点 / (合格点 + 不合格点)
           = 合格点 / (总计量点 − 剔除点)
```

- 剔除点（门控命中、SKIP 缺值）**不计入分母**，与 §5.3、§5.4 一致。
- 可按 时间段（日/月）/ 母线 / `vGrade` 聚合，落 `voltage_quality_*` 统计表（v3.1 §5.2）；日表 rollup 的具体实现见 §5.7。

### 5.7 分钟→日表 rollup（预计算实现，替代 v3.1 §6.1/§6.2）

§5.6 给出判定模型；本节把它跑成 `voltage_quality_daily` 日统计表。**这是 v3.1 §6.1/§6.2 的重写**——v3.1 单分钟判定基于已废弃的 `[low_SV, high_SV]`（v3.2 §1.1 推翻），且未含门控 / 时间对齐 / 主母线判定 / 剔除态，不能沿用。月/年聚合（v3.1 §6.3）是纯加权 `SUM`、与判定口径无关，**完整 SQL 仍沿用 v3.1**。

> 实现形态：Java 编排（`ruoyi-vqms/statistics` 包，挂 RuoYi Quartz 调度，沿用 v3.1 §6.4），内部 = 取数 SQL + 逐分钟判定 + UPSERT；**不是单条 `INSERT...SELECT`**——主母线判定（§5.1.1）含「取指示点最近一条 + 校验合法性 + 兜底」多步逻辑，塞进一条 set-based SQL 可读性差，故拆成 Java 编排。

#### 5.7.1 日表 DDL 增量

`voltage_quality_daily` 沿用 v3.1 §5.2 全部列，**唯一新增 `excluded_minutes`**：

```sql
ALTER TABLE voltage_quality_daily
  ADD COLUMN excluded_minutes INT DEFAULT NULL
    COMMENT '剔除分钟数(门控命中 §5.4 + SKIP缺值 §5.3),不计入 total;均属"本在统计窗口内但被剔除";主母线归属见 §5.7.3 层0'
  AFTER over_limit_minutes;
```

对账铁律：
- `total_minutes` = 参与考核分钟 = `qualified + over_high + over_low`；
- `excluded_minutes` = **在统计窗口内**但被剔除的分钟（门控命中 / `plan_sv_invalid_policy=SKIP`）；**不含**「该分钟主母线是另一条」与「§5.1.1 判定失效」——前者不在窗口、后者整组空档，二者均不计 total 也不计 excluded（见 §5.7.3 层 0）；
- `qualified + over_limit = total`；`total + excluded = 该母线当天充当主母线的全部分钟`；
- 合格率 = `qualified / total`（分母不含剔除）。

`over_high_minutes`/`over_low_minutes` 在 AVC 口径下复用为「偏高 / 偏低」方向（见 §5.7.2），列名与 monthly/yearly 完全兼容。

#### 5.7.2 单分钟判定（替代 v3.1 §6.1）

每个计量点（对齐分钟 × 主母线，§5.6）依次过三关，顺序短路，终态 ∈ {合格, 偏高, 偏低, 剔除}。**前提：主母线归属已由 §5.7.3 层 0 判定，三关只跑被选为主母线的那一行**（组内其他母线该分钟不进三关）：

1. **门控关（§5.4）**：该对齐分钟 `yc_history` 的 yx 门控命中（远方就地总=0 或 AVC投退=0）→ **剔除**。
2. **数据关（§5.3）**：该分钟该母线**无电压样本**（§5.5 缺条：his_curve_sv 无记录），或 `plan_SV` 为废值（`10245`/NULL/缺失）→ 按 `plan_sv_invalid_policy`：`SKIP`→剔除 / `COUNT_UNQUALIFIED`→进不合格 / `FALLBACK`→回退标称±容差判一次。
3. **合格关（§5.3 AVC）**：令 `dev = average_SV − plan_SV`：
   - `|dev| ≤ tolerance_v`（含边界）→ **合格** → `qualified`；
   - `dev > +tolerance_v` → **偏高** → `over_high`；
   - `dev < −tolerance_v` → **偏低** → `over_low`。
   - `over_limit = over_high + over_low`。

> 与 v3.1 §6.1 同构：判定形式（三态 + 边界算合格）不变，只是边界从 `his_curve_sv.low_SV/high_SV` 换成 `plan_SV ± tolerance_v`。`over_high/over_low` 语义从「超国标上下限」自然转为「偏离 AVC 目标值的方向」。

#### 5.7.3 日聚合算法（Java 编排，按组 + 分钟遍历）

> ⚠️ **遍历维度 = 组（`group_num`）× 对齐分钟，不是按 `busbar_num` 遍历**。主母线归属是 §5.1.1 的组级判定，必须**先于三关**用它过滤——否则会把某条母线当副母线的时段也喂进合格率：副母线 AVC 根本没在管，其电压跟目标值对不上不代表 AVC 没控好，误计入会系统性误判（这是本次修订堵的缺口）。每分钟每组的 §5.1.1 判定**整组只做一次**，结果供组内所有母线共用，不按 `busbar_num` 重复查。

每日调度（`stat_date` 次日 `00:0x`，或断点续算回填，游标见 v3.1 §5.2 `precompute_cursor`；**按组推进、组内母线同批算**）对每个组 `group_num` 执行：

```
输入 stat_date, group_num：
① 分两路取该组当天数据，Java 侧按对齐分钟分桶（**不在 SQL 里 join**——避开多条/缺条的笛卡尔积，见 §5.5）：
   - 电压路：his_curve_sv 该组全部 busbar_num 的原始行（**边界故意放宽 ±安全余量**，见 ①-a）
   - yx 路：yc_history 指示点(§5.1.1) + 门控点(§5.4)的原始行（同放宽；放宽下界还顺带修复跨天 yx 阶跃，见 ①-a 末段）
   ①-a **「放宽边界 + 格式校验 + 解析后精确过滤」三步闸门**（兜底 `save_time`/`yc_time` 为 varchar 的脆弱性，§5.5 ⚠️ / §4 第 1 条①）：
       为什么放宽：全表无索引 → range 查询本就全表扫描，WHERE 收窄只省结果集、不省扫描成本。故把 SQL-1/SQL-2 日期边界从「精确当天」放宽一个安全余量（默认 ±1 天，可调），把「是否真属于当天」的权威判断从「字符串范围比较」移交给 Java 侧**解析后的真实时间值**。这样原本因格式异常被字符串排序挤出精确边界、在 DB 层就被无声丢弃的行（「该取没取到」，比「取到但脏」更隐蔽、连日志都没有），只要错位幅度 ≤ 余量就会被 SQL 捞回、进入 Java 校验，降级为可记日志的可追踪失败。
       三步：① 每行时间字段跑正则严格匹配（`^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}(\.\d+)?$`，零填充）→ 不匹配**记日志 + 该格标缺**（电压走数据关 SKIP，§5.7.2 层 2）；② 干净行**解析成真实时间** ts；③ 用 ts（不是字符串）判 `ts ∈ [stat_date, stat_date+1day)` → 在区间内才进分桶，区间外的余量行丢弃（归相邻日 rollup，按真实时间不重复计）。
       残留：错位幅度超过余量的恶性脏写仍可能在 DB 层被丢（如月位漏补零 `'2021-5-7'` 字面排序远离 `'2021-05-0x'`，±1 天捞不回）——靠调大余量（如 ±1 月）或对「当日返回行数远低于预期」做计数告警兜底。DB 边界已不再是正确性脆点，但非 100% catch。
       跨天 yx 阶跃（顺带修复）：yc_history 下界放宽后，对齐分钟 t=当日 00:00 的「最近一条 ≤ t」能取到昨日 23:xx 的 yx 行——精确当天边界会把这种跨天状态截断、首分钟 yx 状态丢失，放宽即修复。
   分桶（对齐分钟 t = FROM_UNIXTIME(ROUND(UNIX_TIMESTAMP(ts)/60)*60)）：
   - 电压桶 keyed by (t × busbar_num)：多条 → average_SV 均值、plan_SV 末条（§5.5）；桶空 → 该格缺条标记
   - yx 桶 keyed by t：取 yc_time ≤ t 的最近一条（阶跃保持，§5.5），指示点与门控各取各
② 逐对齐分钟 t，先跑 §5.1.1 判定该组主母线号 mainBusbarNum(t)（整组只判一次）：
     - 判定成功 → mainBusbarNum(t) = 某条 busbar_num
     - 判定失效（不可用且 default=NULL）→ 该分钟整组无主母线 → 组级空档，
       不计入任何 busbar_num 的 total / excluded（→ §5.7.5 voltage_quality_group_daily.indeterminate_minutes，M2+ 待补）
③ 只对该分钟被选中的那一行 busbar_num = mainBusbarNum(t) 跑 §5.7.2 三关：
     门控关 / 数据关 / 合格关 → 合格 / 偏高 / 偏低 / 剔除(进 excluded)
     累加进 busbar_num = mainBusbarNum(t) 当天的桶；并在其「参与分钟」上累计 max_SV / min_SV / Σaverage_SV
     组内其他 busbar_num 这一分钟直接跳过（不进它们的 total，也不进 excluded——不在它们的统计窗口内）
④ 该组每个 busbar_num 各自 UPSERT 一行 voltage_quality_daily（唯一键 stat_date + busbar_num）
```

判定层次（**层 0 过滤先于三关，是本次修订的核心**）：

| 层次 | 判定 | 不通过的归宿 |
|---|---|---|
| **层 0 主母线归属**（§5.1.1，组级） | 该分钟该组的主母线是哪条？ | 主母线是另一条 → 该母线该分钟**跳过**（不在窗口，不计 total/excluded）；判定失效 → 整组该分钟**空档** |
| **层 1 门控关**（§5.4） | 装置是否退出（远方就地=0 / AVC退）？ | 命中 → **剔除**（进 `excluded`） |
| **层 2 数据关**（§5.3） | `plan_SV` 是否废值/缺值？ | `SKIP`→**剔除**（进 `excluded`）；`COUNT_UNQUALIFIED`→不合格；`FALLBACK`→回退判一次 |
| **层 3 合格关**（§5.3 AVC） | `\|average_SV − plan_SV\|` 是否超 `tolerance_v`？ | 合格 / 偏高（`over_high`）/ 偏低（`over_low`） |

> 「主母线是另一条」（层 0）与「门控命中 / SKIP 缺值」（层 1/2）性质不同：前者是**不在统计窗口**（该母线此刻是副母线），后者是**在窗口内但被剔除**。**只有后者计入 `excluded_minutes`**；前者直接跳过、不留痕。判定失效（层 0 无主母线）也不进 `excluded`，走组级空档——把组级判定失效塞进母线级 `excluded` 会混淆两个粒度，且让 `total + excluded` 对不上"该母线充当主母线的分钟"。

取数 SQL（**两路独立查询**，示意；Java 侧按上 ① 分桶合并，不做 SQL join）：

```sql
-- SQL-1 电压：该组全部母线的原始行。边界故意放宽 ±1 天（安全余量），「是否属于当天」交给 Java 侧
-- 用解析后的真实时间判断（见 ①-a）。全表无索引 → 放宽不增扫描成本，只多取余量行。
SELECT save_time, busbar_num, average_SV, plan_SV
FROM his_curve_sv
WHERE busbar_num IN (SELECT busbar_num FROM busbar WHERE group_num = :group_num)
  AND save_time >= :stat_date - INTERVAL 1 DAY
  AND save_time <  :stat_date + INTERVAL 2 DAY;

-- SQL-2 yx：指示点 + 门控点的原始行。同样放宽（下界放宽还顺带修复跨天 yx 阶跃，见 ①-a 末段）。
SELECT yc_num, yc_data, yc_time
FROM yc_history
WHERE yc_num IN (:yc_num_indicator, :yc_num_remote_local, :yc_num_avc_state)
  AND yc_time >= :stat_date - INTERVAL 1 DAY
  AND yc_time <  :stat_date + INTERVAL 2 DAY;
```

> ⚠️ **SQL-1 的两个外部源隐患**（详见 §4 待决第 1 条）：① `save_time` 是 `varchar` 无格式约束，`>= / <` 是字符串比较——单条脏写会让边界行在 DB 层被**无声丢弃**（「该取没取到」，比「取到但脏」更隐蔽、连日志都没有）。**反制**：①-a 故意放宽边界 ±余量 + Java 侧用解析后的真实时间做权威过滤，把 DB 边界从正确性脆点降级为软预筛。② 全表无索引，范围查询每次**全表扫描**——放宽边界不增扫描成本（这也是①能这么做的依据）；随历史增长线性变慢，向现场争取加 `save_time` 索引 / 否则监控+兜底。
>
> ⚠️ §5.1.1 的指示点判定：指示点原始行由 SQL-2 取回，Java 侧按对齐分钟取「最近一条 ≤ t」+ 合法性校验 + 兜底，得 `mainBusbarNum(t)` 作为**层 0 闸门**，决定该分钟哪条母线进三关——这是接上 §5.1.1 的那一步。
>
> ⚠️ **门控关当前空转**（§5.6 D）：两个门控点 `yc_num` 未补录前，SQL-2 不取它们、yx 桶为空，门控不命中、不剔除；判定实际只跑「数据关 + 合格关」。

#### 5.7.4 月/年 rollup：沿用 v3.1 §6.3

月（daily→monthly）、年（monthly→yearly）是纯加权 `SUM`，与判定口径无关，**完整 SQL 沿用 v3.1 §6.3**（`INSERT...SELECT...GROUP BY...ON DUPLICATE KEY UPDATE`；rate 由分钟数重算，`avg_SV` 按 `total_minutes` 加权，`NULLIF` 防除零）。

唯一建议增量：monthly/yearly 各顺带 `SUM(excluded_minutes)`，保持三层「`total + excluded = 应统计分钟`」对账一致。是否加列待定（不影响合格率算法，纯审计增强）。

#### 5.7.5 组级审计表 `voltage_quality_group_daily`（M2+ 待补）

> 纯审计增强，**不影响合格率算法**。`indeterminate_minutes` 是 §5.7.3 层 0 判定失效产生的组级空档——不计入任何母线的 `total`/`excluded`、在 daily 表无痕迹，是**唯一不能从 daily 反推的量**。本表把它单独记下来，服务"为什么某天 total 比 1440 少很多"的排障。优先级低，M2+ 审计迭代再实现，此处先定型占位。

```sql
-- 组级空档审计（M2+ 待补；落主库 MySQL，与 voltage_quality_daily 同库）
CREATE TABLE voltage_quality_group_daily (
  stat_date             DATE   NOT NULL,
  group_num             BIGINT NOT NULL              COMMENT '→ busbar_group.group_num',
  indeterminate_minutes INT    DEFAULT NULL           COMMENT '§5.1.1 判定失效(无主母线)空档分钟数',
  computed_at           DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '本次计算时间',
  PRIMARY KEY (stat_date, group_num)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='电压质量-组级空档审计(M2+)';
```

组级对账等式（组 g 当天应统计分钟，通常 1440）：

```
Σ_b (total_b + excluded_b)  [b ∈ group，引自 voltage_quality_daily]   = 有主母线且参与/被剔除的分钟
+ indeterminate_minutes      [本表]                                       = 判定失效空档（唯一不可反推）
+ 「未配指示点」分钟（main_indicator_yc_num=NULL，该组当天不建行）         = 组未接入
≈ 1440
```

**为什么必须显式记、不能反推**：从 daily 反推 `1440 − Σ(total+excluded)` 会把「判定失效空档」和「组未接入」混成一个差值。本表把前者单独捞出，从而区分两种故障——「指示点数据质量差（判得到但判失败：陈旧/非法/无兜底）」vs「组根本没配指示点（未接入）」——处置方向完全不同。`total`/`excluded` 内部（门控剔除 vs SKIP 缺值）的进一步拆分是另一个审计增强，不在本表。
